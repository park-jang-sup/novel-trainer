## 2. 관측 넷

### 2-1. AI 는 사실만 재고, 값은 코드가 건다

세션 11 §2 를 그대로 옮긴다.

```
값을 박은 감시    프롬프트가 pass/fail 을 뱉는다
사실만 재는 감시   프롬프트는 관측만 뱉고, 합격선은 코드에 있다   ← 이쪽
```

```
1  T 를 바꿀 때 172건을 다시 안 돌려도 된다. 저장된 관측으로 다시 센다
2  흔들림을 판정이 아니라 관측에서 잰다
3  AI 가 어디서 틀렸는지가 보인다. 'fail' 만 오면 왜 fail 인지 모른다
```

★ **프롬프트가 규칙을 다시 검사하게 하지 마라.** AI 에 오는 172건은 이미 규칙을 통과했다 —
4줄 · 줄당 30자 · 요소 있음 · 요소가 마지막 줄 · 대괄호 없음. 또 물으면 세션 6 §12 의
`AI 는 마지막 관문이다` 가 무너진다.

### 2-2. 프롬프트 v1

```
너는 웹소설 습작 4줄을 읽고 **사실 넷을 보고한다.** 합격 여부는 판정하지 않는다.
합격선은 사람이 코드에서 건다. 네가 할 일은 재는 것뿐이다.

[지문]
{passage}

[답안]
1 {line1}
2 {line2}
3 {line3}
4 {line4}

[결정타 요소] {element}

아래 다섯을 판정해서 JSON 하나만 출력한다. JSON 앞뒤에 아무 말도 쓰지 않는다.

1. delete — 길이 3의 boolean 배열
   i번 줄(i=1,2,3)만 지우고 남은 세 줄을 읽는다.
   4번 줄이 '앞에서 준비된 결과'로 더는 읽히지 않으면 true, 그대로 읽히면 false.
   ★ 문장 연결이 어색해지는 것은 세지 않는다. 4번 줄의 근거가 사라지는지만 본다.
   ★ 지웠는데 오히려 매끄럽게 읽히면 그 줄은 false 다.

2. cue_copied — boolean
   4번 줄이 지문의 [결정타] 줄을 옮겨 놓은 것이면 true.
   ★ [결정타] 줄의 낱말을 가져다 쓰는 것 자체는 true 가 아니다. 그러라고 준 것이다.
     그 낱말을 자기 문장으로 만들었으면 false, 구절째 놔뒀으면 true.
   ★ 4번 줄이 짧은 것은 true 의 근거가 아니다. 짧게 끊는 것은 권장되는 마무리다.

3. foreshadow_used — boolean 또는 null
   지문에 [복선] 줄이 있을 때만 판정한다. 없으면 null.
   1~3번 줄 중 하나라도 그 복선을 집어 쓰면 true, 한 번도 안 쓰면 false.

4. has_actor — boolean
   4번 줄에 인물의 행동이나 상태가 있으면 true, 사물·상황만 있는 명사구면 false.
   ★ 이것만으로 합격이 갈리지 않는다. 사실만 적어라.

5. why — 한국어 한 줄. 40자 이내. 위 넷 중 가장 갈리기 쉬운 하나의 근거만 적는다.

출력 형식(이 꼴 그대로):
{"delete":[false,true,false],"cue_copied":false,"foreshadow_used":null,
 "has_actor":true,"why":"..."}
```

`v0` 에서 바뀐 곳 둘.

```
cue_copied   '낱말만 바꿔 옮긴 것' → '구절째 놔뒀는가'
             ★ 짧은 것이 근거가 아니라고 못 박았다. 요건이 권하는 마무리다
has_actor    v0 에서 cue_copied 의 힌트 한 줄이던 것을 관측으로 올렸다
```

★ `why` 는 채점에 안 쓴다. 사람이 읽으려고 넣었다 — 규칙 때 `checks` 가 화면에서 한 일과
같은 자리다. 흔들림 측정에서 `같은 판정인데 이유가 다른` 경우를 이걸로 본다.

★ 지문의 `why` 필드(작성자가 적은 결정타의 정당화)는 **안 준다.** 학습자가 못 본 것을
AI 에만 주면 AI 가 사람보다 유리한 자리에서 재게 된다. 주는 안은 변종으로 따로 재라.

### 2-3. 관측 ↔ known 넷 — 측정과 예측을 갈라 적는다

```
                          delete(예측)  cue_copied(예측)  foreshadow_used(측정)  has_actor(측정)
좋은 답안 144             1~2 true      false            난2 는 144/144 true    137/144 true
낱낱 나열 8               전부 false    false            8건 중 3 false         8/8 true
빌드업 없이 압축 8         전부 false    false            8건 중 4 false         8/8 true
지문의 결정타 줄을 그대로 8  1개 이상 true  true            8건 중 1 false         ★ 0/8 true
전용 복선미사용 4          1개 이상 true  false            4/4 false             4/4 true
```

**`foreshadow_used` 와 `has_actor` 두 열만 잰 값이다.** 앞의 둘은 설계상 그렇게 나오리라
본 것이고, `4-5장` 1번 측정이 정확히 그것을 시험한다.

`foreshadow_used` 열은 난이도 2 지문 넷에서만 값이 나온다. 실측이 이렇다.

```
지문              복선     낱낱 나열   압축     결정타 복사
at-left-draw     오른팔    false     false    true
at-broken-gate   이빨     ★ true     false    true
at-bell-rope     누이      false     false   ★ false
at-edit-log      초안      false     false    true
```

`낱낱 나열` 은 `1 true / 3 false` 로 갈린다. 하나로 안 닫힌다 — 그것이 답이다.

### 2-4. 관측마다 단독으로 지는 짐이 있다

known 28건이 관측 셋 중 몇 개에 걸리는지 셌다. (`has_actor` 는 합격선 밖이라 안 센다.)

```
delete 단독       9건   난이도 1 의 낱낱·압축 여덟 + at-broken-gate 낱낱
cue_copied 단독   7건   결정타 복사 — 난이도 1 넷 + 난이도 2 셋
foreshadow 단독   4건   전용 복선미사용
둘 이상           8건
그물 0            0건   ★ 0 이어야 한다. 0이다
```

**하나를 빼면 9 · 7 · 4 가 통째로 샌다.** 셋 중 어느 것도 못 뺀다.

★★ **`cue_copied` 단독 7건 중 넷이 난이도 1이다.** 난이도 1은 `foreshadow_used` 가 `null`
이라 예비 그물이 없고, 그 넷은 1~3줄에 진짜 빌드업이 있어 `delete` 도 안 잡는다.
**관측 하나에, 그것도 아직 아무도 안 잰 관측 하나에 전적으로 달려 있다.**
여기서 새면 대안이 없다 — 4-5장 1번에서 이 넷을 따로 봐라.

### 2-5. 예시 — `at-left-draw`

`v0` 은 `at-bell-rope` 을 예시로 들었는데 **그것이 넷 중 유일한 반례였다.**
`at-bell-rope` 의 결정타 복사만 복선을 안 써서 `foreshadow_used` 도 함께 문다.
`cue_copied` 가 유일한 그물인 것은 나머지 셋이다. 세션 6 §6-2 · 지문요건 9-1장
(`지문 1건에서 낸 값은 8건에서 뒤집힌다`) 그 자리다.

```
at-left-draw  [결정타] 한 달을 감춘 왼손 발도   요소 왼손 발도   복선 오른팔

결정타 복사    ... 1~3줄에 빌드업이 있고 복선(오른팔)도 쓴다
              4번 줄: 한 달을 감춘 왼손 발도       ← 구절째 옮겼다
              delete 1개 이상 true · foreshadow_used true
              ★ cue_copied 하나만 잡는다
```

### 2-6. 합격선은 코드에 둔다

```ts
load = delete.filter(Boolean).length          // 0 ~ 3
pass = load >= T && !cue_copied && foreshadow_used !== false
```

`has_actor` 는 **합격선에 안 넣는다.** 3-4장을 보라.

`T` 를 지금 정하지 않는다. `T=1` 과 `T=2` 가 갈리는 자리가 경계 표본이 잴 것이다.

`foreshadow_used !== false` 로 쓰는 이유: `null`(난이도 1)이 통과해야 한다.
`=== true` 로 쓰면 난이도 1 전량이 떨어진다.

## 3. 규칙으로 내리는 안 — 쟀고 닫혔다

### 3-1. `echoLen` — 근거가 두 번 바뀌고 결론은 유지된다

`지문의 결정타 줄을 그대로` 는 베낀 것이니 문자열 비교로 잡힐 여지가 있다. 9장이 지문
전체와 대서 버렸는데, `elementCue` 한 줄과만 대면 다를 수 있다. 쟀다.

```
1차  지문 전체와 댄다              좋은답안 9 · 베끼기 7    겹친다        9장
2차  elementCue 와만 댄다          좋은답안 9 · 베끼기 5    더 겹친다     ★ 결함 위의 값
3차  at-broken-gate 결함을 걷는다   좋은답안 9 · 베끼기 7    여전히 겹친다  ★ 구조다
```

2차의 원인을 `cue 가 짧아서` 로 읽었는데 틀렸다. `at-broken-gate` 의 `elementCue` 가
`부러진 창끝`(5자)이라 짧게 끊은 좋은 답안 `부러진 창끝.` 과 **글자까지 같았다.**
픽스처 결함이었고 `04e87e1` 이 재료를 고쳤다(세션 9 §2 — 검사를 더하지 말고 재료를 바꾼다).

결함을 걷고도 겹친다. 남은 동률이 `at-bell-rope 7 대 7` 인데 **이건 정상이다** —
좋은 답안이 `[결정타] 줄을 문장으로 만든 것`이고, 그것이 이 드릴이 시키는 일이다.

```
★ 규칙으로 내리는 안은 닫혔다. 다만 4-2장 C2 표본 위에서 다시 재라 —
  지금 닫힌 것은 '복사·붙여넣기' 표본 위에서다
```

### 3-2. `has_actor` 는 규칙으로 걸면 안 된다

```
결정타 복사 8건     마지막 줄이 '-다' 로 끝남   0/8      전부 명사구
좋은 답안 144건     137/144                  ★ 7건이 명사구
낱낱나열·압축 16    16/16                    안 걸린다
전용 4건           4/4                      안 걸린다
```

`0/8` 대 `137/144` 로 갈리는 축이 맞는데, **오탐 7건이 0장 요건이 넣으라고 한
`짧게 끊은 마지막 줄`이다.** 2부 23-2가 권하는 마무리이고 지문마다 넣게 한 표본이다.
규칙으로 걸면 요건이 요구한 표본을 죽인다.

```
태윤의 왼발 페인트. · 왼발 페인트. · 왼손 발도. · 왼쪽 더듬이. ·
부러진 창끝. · 갈라진 얼음. · 수정 기록.
```

### 3-3. 그래서 `has_actor` 는 관측 넷째다

규칙이 못 가르는 자리이므로 AI 자리가 맞다. 물어야 할 것은 이것이다.

```
명사구 하나뿐인 4번 줄과, 짧지만 결정타를 자기 것으로 만든 4번 줄을 가를 수 있는가
```

**그 오탐 7건이 그대로 경계 표본이다.** 새로 짤 것이 없다 — 이미 `goods` 안에 있다.

### 3-4. ★ 관측을 늘리는 것과 합격선에 넣는 것은 다르다

`has_actor` 를 `pass` 식에 넣고 싶어진다. 넣지 마라.

```
넣으면      좋은 답안 7건이 즉시 떨어진다. 3-2장 수 그대로다
안 넣으면    관측으로 기록되고, 1번 측정에서 cue_copied 오답과 상관이 있는지를 본다
            ★ 상관이 있으면 그때 넣을지 판단한다. 지금은 근거가 없다
```

이것이 0장 계보의 네 번째 얼굴이다.

## 4. 경계 표본

### 4-1. `goods` 144건으로는 오탐을 못 잰다

세션 11 §8 재는 순서 5번.

```
표본이 요건을 건드리는지 봐라 — 안 건드리면 오탐 0이 표본 선택의 결과다
```

`goods` 144건은 사람이 **빌드업이 있게** 쓴 것이라 구조적으로 known 넷을 피한다.
`오탐 0/144` 는 프롬프트가 좋아서 나온 수가 아니라 처음부터 보장된 수다.

★ 그래도 버리지 않는다. **하한선 확인용이다** — 여기서 오탐이 나오면 프롬프트가
망가진 것이니 즉시 안다. 다만 `0` 이 나와도 아무 말도 안 해준다.

### 4-2. ★ known 표본 자체도 쉽다

```
결정타 복사 8건이 elementCue 와 8/8 완전 일치다
  → 학습자가 지문 줄을 통째로 복사·붙여넣기 한 경우만 표본에 있다
    낱말 하나만 바꾸거나 조사만 떼어도 그 표본은 없다
```

그러면 `cue_copied` 를 재는 것이 **복사·붙여넣기를 잡는가만 재는 것**이 된다.
AI 는 그건 당연히 잡는다. 그리고 3-1장의 `9 대 7` 도 이 표본 위의 값이다.

**그래서 `C1`·`C2` 는 부록이 아니라 본 측정이다.** 아래 셋이 다 그 위에서 다시 재진다.

### 8-1. 실측 길이

```

★ **v0 과 수가 다른 이유는 우리 쪽에 있다.** 단가가 아니라 틀이 늘었다.

```

`~900자` 로 어림잡았다가 재니 `1,010` 이었다. 0장 계보 셋째를 이 문서가 또 저질렀다 —
**틀 길이는 우리가 잰 값이지 추정할 값이 아니다.**

`cached_tokens` 컬럼이 있는 이유가 여기다. 다만 아래 수를 보면 지금은 안 켠다.

### 8-2. 계산

### 8-4. 그래도 마개는 켠다

`$1.80` 은 **우리가 계획한 호출**의 값이다. 세션 6 §12 가 막으려던 것은 계획한 호출이
아니라 **루프에 걸린 호출**이다.

```
적혀 있는 것과 걸리는 것은 다르다     세션 11 §8-1
```

비용이 싸다는 것이 마개를 미룰 근거가 되면 안 된다. 이 절을 그렇게 읽지 마라.

`가-1`(킬스위치)과 `가-2`(지출 상한)는 **호출 자리에 놓여야 마개다.**

```
A  lib/ai/gate.ts   판정만 하는 순수 함수 — kill_switch · 오늘 sum(cost_usd) · quota
                    verify 에 병을 문다. kill_switch=true 면 deny 가 나오는가
B  route.ts 가 gate 를 부르고 Gemini 를 부른다 · ai_usage_log 에 쓴다
   @google/genai 가 여기서 들어온다
```

`A` 를 혼자 오래 두면 `import 0건` 짜리가 또 생긴다 — `@anthropic-ai/sdk` 가 그 꼴이다.
`A` 와 `B` 를 같은 날 붙일 게 아니면 `A` 도 미뤄라.

```
@anthropic-ai/sdk   package.json 한 줄이 전부. import 0건. 뺀다
@google/genai       npm latest 2.19.0. ★ B 와 같은 커밋에 넣는다
```

## 10. 미결 — 문서 둘이 갈린다

```
docs/10단계_지문요건.md 12장   결론(title 변경)은 살아남고 근거가 바뀐다
04_전투씬_작법_종합정리.md 15-1  이름을 바꿀 필요가 없어졌다
```

같은 사실에서 반대 결론이다. **AI 심사를 막지는 않는다** — 단계 이름과 `summary` 문제이지
판정 문제가 아니다. 다만 `stages` 를 건드릴 때 하나를 지워야 한다.

지금 말할 수 있는 것은 이렇다. 원자료는 턴제를 3위, 감정을 1위에 놓는다. `근거가 없다` 는
틀렸지만 `이름이 자료의 3위에 붙어 있었다` 는 맞다. `04` 15-1 은 근거의 **유무**만 보고
순위를 안 봤다. 그리고 그 절 자신이 `[B-BT-02] 턴제 자체는 노잼` 을 인용하며 판정 방향을
`의도가 붙어 있는가` 로 돌리라고 적는다 — **자기 문장이 이름을 3위에 묶는 것을 경계한다.**

★ 이건 `04` 문서의 목차와 12·15장만 읽고 낸 판단이다. 정할 때 둘을 나란히 놓아라.

`04` 15-2 의 드릴 후보 일곱은 11단계 이후 재료다. 여기서 다루지 않는다.
