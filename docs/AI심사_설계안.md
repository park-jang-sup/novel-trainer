### 2-2. 프롬프트 v1

```
너는 웹소설 습작 4줄을 읽고 **사실 넷을 보고한다.** 합격 여부는 판정하지 않는다.
합격선은 사람이 코드에서 건다. 네가 할 일은 재는 것뿐이다.

[지문]

[답안]

2 {line2}
3 {line3}
4 {line4}

[결정타 요소] {element}

아래 다섯을 판정해서 JSON 하나만 출력한다. JSON 앞뒤에 아무 말도 쓰지 않는다.

1. delete — 길이 3의 boolean 배열
   i번 줄(i=1,2,3)만 지우고 남은 세 줄을 읽는다.
   4번 줄이 '앞에서 준비된 결과'로 더는 읽히지 않으면 true, 그대로 읽히면 false.
   ★ 문장 연결이 어색해지는 것은 세지 않는다. 4번 줄의 근거가 사라지는지만 본다.
   ★ 지웠는데 오히려 매끄럽게 읽히면 그 줄은 false 다.

2. cue_copied — boolean
   4번 줄이 지문의 [결정타] 줄을 옮겨 놓은 것이면 true.
   ★ [결정타] 줄의 낱말을 가져다 쓰는 것 자체는 true 가 아니다. 그러라고 준 것이다.
     그 낱말을 자기 문장으로 만들었으면 false, 구절째 놔뒀으면 true.
   ★ 4번 줄이 짧은 것은 true 의 근거가 아니다. 짧게 끊는 것은 권장되는 마무리다.

3. foreshadow_used — boolean 또는 null
   지문에 [복선] 줄이 있을 때만 판정한다. 없으면 null.
   1~3번 줄 중 하나라도 그 복선을 집어 쓰면 true, 한 번도 안 쓰면 false.

4. has_actor — boolean
   4번 줄에 인물의 행동이나 상태가 있으면 true, 사물·상황만 있는 명사구면 false.
   ★ 이것만으로 합격이 갈리지 않는다. 사실만 적어라.

5. why — 한국어 한 줄. 40자 이내. 위 넷 중 가장 갈리기 쉬운 하나의 근거만 적는다.

출력 형식(이 꼴 그대로):
{"delete":[false,true,false],"cue_copied":false,"foreshadow_used":null,
 "has_actor":true,"why":"..."}
```

`v0` 에서 바뀐 곳 둘.

```
cue_copied   '낱말만 바꿔 옮긴 것' → '구절째 놔뒀는가'
             ★ 짧은 것이 근거가 아니라고 못 박았다. 요건이 권하는 마무리다
has_actor    v0 에서 cue_copied 의 힌트 한 줄이던 것을 관측으로 올렸다
```

★ `why` 는 채점에 안 쓴다. 사람이 읽으려고 넣었다 — 규칙 때 `checks` 가 화면에서 한 일과
같은 자리다. 흔들림 측정에서 `같은 판정인데 이유가 다른` 경우를 이걸로 본다.

★ 지문의 `why` 필드(작성자가 적은 결정타의 정당화)는 **안 준다.** 학습자가 못 본 것을
AI 에만 주면 AI 가 사람보다 유리한 자리에서 재게 된다. 주는 안은 변종으로 따로 재라.

### 2-4. 관측마다 단독으로 지는 짐이 있다

known 28건이 관측 셋 중 몇 개에 걸리는지 셌다. (`has_actor` 는 합격선 밖이라 안 센다.)


**하나를 빼면 9 · 7 · 4 가 통째로 샌다.** 셋 중 어느 것도 못 뺀다.

★★ **`cue_copied` 단독 7건 중 넷이 난이도 1이다.** 난이도 1은 `foreshadow_used` 가 `null`

**관측 하나에, 그것도 아직 아무도 안 잰 관측 하나에 전적으로 달려 있다.**
여기서 새면 대안이 없다 — 4-5장 1번에서 이 넷을 따로 봐라.

### 2-6. 합격선은 코드에 둔다

```ts
load = delete.filter(Boolean).length          // 0 ~ 3
pass = load >= T && !cue_copied && foreshadow_used !== false
```

`has_actor` 는 **합격선에 안 넣는다.** 3-4장을 보라.

`T` 를 지금 정하지 않는다. `T=1` 과 `T=2` 가 갈리는 자리가 경계 표본이 잴 것이다.

`foreshadow_used !== false` 로 쓰는 이유: `null`(난이도 1)이 통과해야 한다.
`=== true` 로 쓰면 난이도 1 전량이 떨어진다.

## 3. 규칙으로 내리는 안 — 쟀고 닫혔다

### 3-1. `echoLen` — 근거가 두 번 바뀌고 결론은 유지된다

`지문의 결정타 줄을 그대로` 는 베낀 것이니 문자열 비교로 잡힐 여지가 있다. 9장이 지문
전체와 대서 버렸는데, `elementCue` 한 줄과만 대면 다를 수 있다. 쟀다.

```
1차  지문 전체와 댄다              좋은답안 9 · 베끼기 7    겹친다        9장
2차  elementCue 와만 댄다          좋은답안 9 · 베끼기 5    더 겹친다     ★ 결함 위의 값
3차  at-broken-gate 결함을 걷는다   좋은답안 9 · 베끼기 7    여전히 겹친다  ★ 구조다
```

2차의 원인을 `cue 가 짧아서` 로 읽었는데 틀렸다. `at-broken-gate` 의 `elementCue` 가
`부러진 창끝`(5자)이라 짧게 끊은 좋은 답안 `부러진 창끝.` 과 **글자까지 같았다.**
픽스처 결함이었고 `04e87e1` 이 재료를 고쳤다(세션 9 §2 — 검사를 더하지 말고 재료를 바꾼다).

결함을 걷고도 겹친다. 남은 동률이 `at-bell-rope 7 대 7` 인데 **이건 정상이다** —
좋은 답안이 `[결정타] 줄을 문장으로 만든 것`이고, 그것이 이 드릴이 시키는 일이다.

```
★ 규칙으로 내리는 안은 닫혔다. 다만 4-2장 C2 표본 위에서 다시 재라 —
  지금 닫힌 것은 '복사·붙여넣기' 표본 위에서다
```

### 3-3. 그래서 `has_actor` 는 관측 넷째다

규칙이 못 가르는 자리이므로 AI 자리가 맞다. 물어야 할 것은 이것이다.


**그 오탐 7건이 그대로 경계 표본이다.** 새로 짤 것이 없다 — 이미 `goods` 안에 있다.

### 3-4. ★ 관측을 늘리는 것과 합격선에 넣는 것은 다르다

`has_actor` 를 `pass` 식에 넣고 싶어진다. 넣지 마라.


이것이 0장 계보의 네 번째 얼굴이다.

## 10. 미결 — 문서 둘이 갈린다

```
docs/10단계_지문요건.md 12장   결론(title 변경)은 살아남고 근거가 바뀐다
04_전투씬_작법_종합정리.md 15-1  이름을 바꿀 필요가 없어졌다
```

같은 사실에서 반대 결론이다. **AI 심사를 막지는 않는다** — 단계 이름과 `summary` 문제이지
판정 문제가 아니다. 다만 `stages` 를 건드릴 때 하나를 지워야 한다.

지금 말할 수 있는 것은 이렇다. 원자료는 턴제를 3위, 감정을 1위에 놓는다. `근거가 없다` 는
틀렸지만 `이름이 자료의 3위에 붙어 있었다` 는 맞다. `04` 15-1 은 근거의 **유무**만 보고
순위를 안 봤다. 그리고 그 절 자신이 `[B-BT-02] 턴제 자체는 노잼` 을 인용하며 판정 방향을
`의도가 붙어 있는가` 로 돌리라고 적는다 — **자기 문장이 이름을 3위에 묶는 것을 경계한다.**

★ 이건 `04` 문서의 목차와 12·15장만 읽고 낸 판단이다. 정할 때 둘을 나란히 놓아라.

`04` 15-2 의 드릴 후보 일곱은 11단계 이후 재료다. 여기서 다루지 않는다.
