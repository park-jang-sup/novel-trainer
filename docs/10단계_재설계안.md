# 10단계 재설계안

★★ **이 문서는 제안이다. 아무것도 안 고쳤다.** 코드·픽스처·설계안 본문 모두 그대로다.
정하고 나서 고친다. 이 프로젝트가 물린 자리 대부분이 **재기 전에 고친 자리**였다.

세션 15 끝에 열린 물음이다.

```
왜 줄 수가 고정되어야 하는가
전투씬은 2줄일 수도 100줄일 수도 있는데 4로 못 박는 근거가 무엇인가
정답이 있는데 그릇이 못 담으면, 고칠 것은 그릇이 아닌가
```

## 1. 조사 — `exact_sentences 4` 가 어디서 왔나

설계서 `ch03_scene.json` 135문항 중 `exact_sentences` 는 **6건뿐**이고,
그 6건이 두 드릴이다.

```
3-06 F1  빌드업 세 문장 뒤에 결정타 한 문장          = 3 + 1 = 4
3-09 F1  억압 두 문장, 해방 두 문장. 비율을 지키라    = 2 + 2 = 4
```

★ **고정된 것은 줄 수가 아니라 비율이다.** `4` 는 장면 길이에 대한 주장이 아니라
`3:1` 을 눈에 보이게 만드는 최소 그릇이다. `3-09` 가 같은 4인데 안이 `2+2` 이고
`비율을 지키라` 고 명시한 것이 그 증거다.

난이도별로도 갈린다.

```
난이도 1   exact_sentences 6건 · min_scenes 6건     칸을 고정한다
난이도 2   exact_sentences 0건 · min_scenes 18건    푼다
난이도 3   exact_sentences 0건 · max_action_sentences  다른 것으로 잡는다
```

같은 드릴 3-06 안에서도 사다리다.

```
F1  exact_sentences 4 · 30자          배치를 고정한다   ← 지금 10단계
F2  min_scenes 2 · 240자              이유를 깔라
F3  max_action_sentences 3 · 260자    동작 셋 이하
```

**설계 의도로는 앞뒤가 맞는다.** 문제는 다른 데 있다.

## 2. 그 눈금이 본론을 밀어냈다

### 2-1. 3:1 은 원문에서 안 나온다

참고 산문 셋(격투 · 무협 · 판타지)에서 빌드업 대 결정타는 3:1이 아니다.

```
격투    미트 훈련 · 상대의 성격 · 조절이 안 됨 → 가드가 열림 → 훅
무협    진법 원리 · 두통 · 화살 · 균열 · 창 파괴 → 심장을 찌른다
판타지  도약 봉쇄 · 4중첩 · 마력 장악 → 머리가 날아간다
```

**수십 대 하나다.** 3:1로 보이는 것은 짧게 접었을 때뿐이고, 그때 조화로워
보이는 것은 비율이 맞아서가 아니라 짧아서다.

★ 그리고 `04 2장`이 **전투씬은 그다지 중요한 파트가 아니다** 로 시작한다.
근거는 독자 행동이다 — 독자가 넘긴다. 중요한 것은 그 앞에 깔린 것이라는 뜻이고,
그러면 `빌드업 셋` 이라는 수가 작아도 너무 작다.

### 2-2. F1이 잡는 것과 못 잡는 것

```
F1이 잡는 것    마지막 한 수가 승부를 가르는가
F1이 못 잡는 것  왜 싸우는가 · 수싸움 · 한계 · 극복
                ★★ 이것이 04 문서의 본론 전부다
```

### 2-3. 난이도가 아니라 순서다

지금 구조는 `난1 → 난2 → 난3` 인데 이것은 **시험 문항의 구조**다.
이 프로젝트는 시험이 아니라 작법을 배우는 자리다.

★ 어렵게 내는 것이 목적이 아니다. **쉽게 이해하고 따라갈 수 있는 것**이 먼저다.
단이 오르는 것은 어려워지는 것이 아니라 **다루는 단위가 커지는 것**이어야 한다.

## 3. ★★★ 진짜 원인 — 채점 3단 중 하나만 구현했다

설계서 `meta.grading` 에 이미 적혀 있다.

```
stage1  constraints — 자동 판정
stage2  checklist  — 반자동 요소 확인
stage3  reference  — 참고용 노출, 점수 미반영
```

★★ **저장소에 `checklist` 를 쓰는 코드가 한 줄도 없다.** stage2가 통째로 없다.

그래서 stage1이 혼자 다 하려 했고, 그 결과가 `exact_sentences 4 · 30자` 다.
**요건이 빡빡해진 것은 설계가 나빠서가 아니라 채점 칸 하나로 셋을 하려 해서다.**

그리고 `answer_policy` 가 이렇게 적혀 있다.

```
모든 문항의 산출물은 재작성 또는 신규 작성된 원고. `틀린 이유 서술` 금지.
```

**처음부터 `채점` 이 아니라 `요건 확인` 으로 설계돼 있었다.**

## 4. 제안 — 빈칸으로 간다

전투씬만 따로 떼어 쓰게 하는 것부터가 `04 2장` 과 어긋난다. 혼자 있는 전투씬을
안 쓰게 하려면 **주변을 고정하고 빈칸을 준다.**

```
갈래 1  사이를 채운다      동작 사이에 의도를 끼운다        04 6장
갈래 2  앞을 채운다        왜 이 싸움을 하는가             04 2장
갈래 3  꾸민다            주어진 전투를 다시 쓴다
갈래 4  직접 짠다         상황·복선·결정타를 학습자가 짠다
```

★ `1 → 2 → 3 → 4` 가 **단위가 커지는 순서**다. 문장 하나 끼우기에서 시작해
나중에 지문 자체를 짜게 된다.

### 4-1. 실물 — 갈래 1

```
테마   복수
표지   그 마수가 지나간 자리에는 번개 모양 자국이 남는다
       ★ 땅·나무·시신에 남는 흔적이다. 마수의 몸에 있는 것이 아니다
상황   세연은 작년에 동생을 잃었다. 시신 옆 나무에 그 자국이 있었다.
       숲 어귀에서 같은 자국을 찾아 사흘을 따라 들어왔다.
       무너진 성문 아래에서 마주쳤다.
급소   목 — 비늘 사이의 역린
```

```
  세연은 부러진 창끝을 두 손으로 고쳐 쥐었다.

  ①  ______________________________

  마수가 몸을 낮추고 머리를 들이밀었다.

  ②  ______________________________

  창끝이 마수의 목으로 들어갔다.
```

```
조건
  ①  세연이 이 순간 무엇을 생각하는지. 한 문장에서 두 문장
  ②  세연이 무엇을 보고 목을 노리기로 했는지. 한 문장에서 두 문장
```

채운 예 둘. **둘 다 통과해야 한다.**

```
가
  ①  동생이 죽고 이 순간이 오기만을 신께 빌었다. 그런데 막상 손이 떨렸다.
  ②  머리를 낮추자 목을 덮은 비늘이 밀려 올라갔다. 그 사이로 역린이 드러났다.

나
  ①  기회는 한 번이다. 빗나가면 두 번째는 없다.
  ②  들이미는 머리를 따라 목이 길게 늘어났다. 비늘이 얇은 자리가 거기였다.
```

★ `가` 는 표지로 개체를 확인하면서 동시에 목이 열리는 것을 본다.
`나` 는 표지를 안 쓰고 자세만 본다. **개체 확인은 앞에서 이미 끝났으니 둘 다 맞다.**

### 4-2. 왜 이 모양인가

```
이음매가 안 깨진다   앞뒤가 고정이라 학습자가 흐름을 못 망친다
의도를 그 자리에서   04 6장의 `왜 그렇게 치는가` 가 정확히 ①②다
빈칸이 작다         자유도가 낮아 채점이 선다
전투씬을 혼자 안 쓴다  04 2장과 맞는다
```

### 4-3. 크기 사다리

같은 지문을 그대로 두고 빈칸만 넓힌다.

```
1단  ① 하나만
2단  ①②                       ← 4-1의 실물
3단  ①②③ + 동작 줄 하나를 비운다
4단  동작 줄을 다 비우고 앞뒤만 남긴다   → 갈래 2
5단  상황·복선·결정타를 학습자가 짠다   → 갈래 4
```

★ 조건은 계속 `무엇이 들어간다` 뿐이고, 단이 오를수록 **비는 칸이 늘 뿐**이다.

## 5. ★★ 금지 조건을 안 쓴다

```
소설은 자유도가 높고 정답과 오답의 경계가 뚜렷하지 않다.
`이건 반드시 오답이다` 라고 할 만한 것이 없다.
★ 다만 반드시 써야 하는 조건이나 상황이면 그때는 요구한다.
```

지금 설계서 제약의 절반이 `forbid_*` 인데, 실물을 그리면서 **이유를 못 대는 금지가
붙기 쉽다**는 것을 겪었다. 첫 실물에 `이빨 금지`·`마수 금지` 를 붙였는데, 둘 다
제약 목록에 있어서 붙인 것이지 배우는 데 필요해서가 아니었다.

```
버린다   forbid_direct_mention · forbid_pattern 같은 금지형 조건
남긴다   `무엇이 들어간다` · 길이 · 문장 수
```

★ 그리고 **특정 낱말을 요구하는 것도 조심해야 한다.** `②에 표지가 들어간다` 를
조건으로 걸면 학습자가 그 낱말만 박아 넣는다. `cue_copied 40/40` 이 복사만 재고
있는 것과 같은 병이다(설계안 4-2장).

## 6. 채점이 어디까지 서나

```
stage1  자동
  ①②  각각 max_sentences 2 · min_chars
  ★ 금지가 하나도 없다

stage2  반자동 — 지금 구현 0건
  ②가 마지막 줄과 이어지는가
  ★★ 이 칸 하나만 본다. ①은 안 봐도 된다

stage3  참고용 — 점수 없음
  같은 자리에서 원문이 어떻게 했는지 보여 준다
  ★ AI 유사도 채점은 여기까지만. 점수를 매기면 delete 와 같은 병에 걸린다 —
    연속값이라 흔들림을 먼저 재야 하고(12-4장), 유사도가 높다고 좋은 글도 아니다
```

★★ **stage2가 볼 것이 한 칸뿐이다.** 지금 F1은 답안 전체가 이어지는지를 봐야
했는데, 여기서는 `②` 하나다. 그것이 `지목` 관측이 실제로 잴 수 있는 크기다.

★★★ **문항 설계에서 나온 물음과 AI 관측이 풀 물음이 같은 자리로 모인다.**
`②가 마지막 줄과 이어지는가` 는 세션 15 4장의 `지목` 물음을 쓰는 쪽에서 본 것이다.

```
지목 물음   마지막 줄이 왜 통하는지, 앞의 무엇을 드는가   ← 읽는 쪽
빈칸 문항   이 결정타가 통하려면 앞에 무엇이 있어야 하는가  ← 쓰는 쪽
```

## 7. ★★ 재료를 다시 봐야 한다

실물이 세 번 만에 섰다. 두 번은 **재료가 발목을 잡았다.**

```
1회  조건에 이유가 없었다. 이음매가 안 맞았다
2회  복선이 `이빨` 이라, 급소가 아닌 것을 급소처럼 쓰게 됐다
     → `이빨이 어긋나 있었다` 같은 뜻 없는 문장이 나왔다
3회  표지를 `흉터` 라 부르니 마수의 몸에 있는 것처럼 썼다
     → 흉터는 마수가 지나간 자리에 남는 자국이다
```

★★ **재료가 이상하면 재료를 고쳐야지 문장을 비틀 일이 아니다.**
조건을 채우려고 뜻 없는 문장을 만든 것이 이 대화에서 세 번째다
(`숨을 고르며 거리를 벌렸다` 포함).

```
살릴 수 있는 것    상황의 뼈대 — 복수 · 마수 · 무너진 성문
다시 써야 하는 것   복선 · 요소 · 급소가 어디인가 · 개체를 가릴 표지가 있는가
                 ★ 8건 전부 이 검사를 통과하는지 봐야 한다
```

★ 재설계 전이라도 이 검사는 값어치가 있다. `at-broken-gate` 는 지금 형태로도
복선이 급소를 안 가리킨다.

관측 축(`delete` · `cue_copied` · `foreshadow_used` · `has_actor`)은 **문항 형식이
아니라 답안의 성질**을 잰다. 문항이 바뀌어도 `delete 가 죽었다` 는 그대로다.

★ 다만 **표본이 바뀌면 다시 재야 한다.** 12장의 수는 `4줄 완전문` 위의 값이다.
세션 15 10-3장의 `결론을 4줄 밖으로 밀지 마라` 가 그대로 걸린다.

### ★ 경계 표본의 틀은 살아 있다

`docs/경계표본_작성시트.md` 의 `L` 정의(지목형)와 `가 면 → 나 면` 순서 원칙은
문항이 바뀌어도 그대로다. 버리는 것은 `A_write.md` 의 자리 배치뿐이다.
