```
축3  전체 null 비율         —     26.7%      13.3%       ≤40%   ✓
support = 1                0/180    0/180    12/180
```

**두 문안 다 못 넘었다. Pro 를 안 썼다 — $2.4 를 아꼈다.**

### 11-1. ★★★ 판정선을 먼저 박아 두 번 막혔다

```
1  1회로 냈으면 넘겼다
   p1 한 회차는 압축 6/8 이었다. 5회 다수결은 5/8 이다
   ★ 계보 `한 번 잰 것과 여러 번 잰 것은 다르다` 가 처음으로 **사전에** 막았다.
     지금까지는 전부 사후에 물린 것이었다

2  `C-1 을 고쳤으니 P1b 가 낫다` 로 읽고 싶은 자리인데 수가 반대다
   ★ 문안을 먼저 보면 그 문안이 잘할 것 같은 쪽으로 선이 그어진다.
     그래서 문안보다 판정선을 먼저 박았다
```

### 11-2. ★★ 마개를 고쳤더니 나빠졌다

`P1b` 는 `P1` 에서 `C-1` 마개 한 문장만 다르다.

```
넣으니   후보가 하나 늘어 `없다` 를 덜 낸다   압축 5/8 → 3/8 · 전체 26.7% → 13.3%
        고를 것이 늘어 더 흔들린다          5회 내내 23 → 22
```

★★ **`C-1` 결함이 있는 `P1` 이 고친 `P1b` 보다 낫다.** 뒤집어 적지 마라.

★ 그리고 `C-1` 은 **문안으로 안 고쳐진다.** `v2` 는 같은 마개가 있는데도
`delete[0]` 이 `1/180` 이었고, `P1b` 는 마개를 넣어도 `12/180`(6.7%)이다.
세 자리가 고르면 33% 여야 한다. **문안 셋이 같은 자리에서 같은 수를 낸다.**

### 11-3. ★★★ 마개 이전(移轉) 결함 — 새 계보

`v2` 의 `delete` 문안은 `C-1`·`C-2`·`C-4` 를 각각 막는 문장 셋을 갖고
`verify` 가 그 셋을 물고 있었다. `point` 로 옮기며 **`C-2`·`C-4` 는 옮겼는데
`C-1` 만 빠졌다.** `support = 1` 이 `0/180` 이 된 이유다.

```
문안 결함    쓸 때 안 떠올린 것
★ 이전 결함  이미 막아 둔 것을 새 문안으로 옮기며 빠뜨린 것
```

★★ `verify` 에 **마개 이전 검사**를 만들었다. 세 마개를 **문안마다 한꺼번에**
문다. 하나씩 검사하면 다음에도 하나가 빠진다.

★ `point`(P1)는 `C-1` 이 **빠진 채로 남는다.** 그것이 `4-2-2` 를 낸 문안이고,
고치면 그 수를 낸 문안이 사라진다. **빠져 있다는 것 자체를 검사가 기억한다.**

## 12. ★★★ `delete 사망` 을 고쳐 적었다

```
             delete   P1     P1b
낱낱 여덟      8/8     1/8    1/8    ★★ 지목은 두 문안 다 못 잡는다
압축 여덟      4/8     5/8    3/8
good 여덟      4/8     0/8    0/8    ★ 지목이 확실히 낫다
```

★★★ **`사망` 이 아니라 `혼자로는 못 쓴다` 다.**
세션 13이 `delete` 를 내릴 때는 대안이 없었다. 대안을 두 벌 만들어 재 보니
그 대안이 못 하는 일을 `delete` 가 한다.

★ 세션 13 12-3장의 나머지 진단(D-1/D-2 · low·high 둘 다 안 섬)은 그대로 맞다.
틀린 것은 `사망` 이라는 낱말 하나다.

★★ **둘을 같이 쓰는 것은 아직 안 쟀다.** 한 호출로 둘을 물으면 간섭할 수 있고,
따로 물으면 비용이 두 배다. 그리고 `T` 식이 바뀐다 — `passesAt` 이
`load >= T` 하나인데 관측이 둘이면 식이 둘을 받아야 한다.
**지금 고치지 마라. 같이 쓰는 것이 서는지부터 재라.**
