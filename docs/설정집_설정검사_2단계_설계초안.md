# 설정집 × 설정검사 — 2단계 설계 초안 (코드 전)

작성: 세션 55 · 근거: `docs/설정집_설정검사_통합설계_v1.md` §4-2(저장소) · §5-2(화면) · §5-3(편집) · 1단계 실측(`lib/setting/`, STATUS 6번)
범위: **저장소(관찰/정본 분리) · 개체 페이지 · 회차 슬라이더 · decisions.** 검사 ②③④·작품 사전·메모 import 는 3~5단계.
상태: 마이그레이션 SQL 초안 `migrations/setting/0001_setting_init.sql` + 이 문서의 화면 와이어 텍스트. **코드도 DB 실행도 아직 없다.**

## 0. 1단계가 2단계에 넘기는 것

| 1단계에서 확정 | 2단계에 박히는 자리 |
|---|---|
| 기본 경로 MEDIUM · 3회 · 합집합. support 1/N 은 weak | `observations.support/runs`. 화면은 support 를 회색 농도로, weak 카드는 "약함" 배지 |
| 카드는 순수 함수(observations·events·decisions). 저장 안 함 | `decisions.dismiss_key` 만 저장. 카드 목록은 요청마다 `detectStateChangeWithoutEvent` |
| 관계·전이 → 상태 물질화 | `observations.source ∈ {from_relation, from_transition}`. 화면에 "관계에서" "사건에서" 꼬리표 |
| 소속은 set. 겹소속 정상 | 카디널리티는 코드(attributes.ts). 개체 페이지 "소속" 줄은 값을 여럿 나열 |
| 표기 축약(서울경찰청장 ⊃ 경찰청장)은 카드 아님 | 확인 필요 탭이 아니라 용어 탭 "표기 흔들림 후보" 에 붙는다(4단계 자리, 지금은 info 줄) |
| 골든 62/0 는 손 추출본, 실제 추출은 합집합 59/1 | 2단계 완료 기준은 골든이 아니라 **되돌리기 동작 · 카드 = 순수 함수 확인**(설계 §11) |

## 1. 저장소 — 관찰과 정본을 나누는 이유 (한 번 더)

```
observations   원고 출처 · 점(회차, 오프셋) · 불변 · 회색     ← 검사기의 입력
canonical      작가 소유 · 구간[from_ep, to_ep] · 화면의 "지금 상태"   ← 작가 액션으로만 생긴다
```

- 같은 테이블에 status 로 두면 "19세(1화 관찰)" 와 "19세(1~13화 정본)" 가 같은 행 모양을 강요받는다. 점과 구간은 다르다.
- 승격 = 관찰 행을 정본으로 **복사**(`source = promoted_from:<obs id>`). 관찰은 그대로 남아 검사기가 계속 본다.
- 되돌리기 = `decisions` 행 삭제. 정본 승격을 되돌리면 canonical 행 삭제. 둘 다 "행 삭제" 하나로 끝나야 한다(한계 문서 4번).

회차 투입 한 번의 쓰기 순서 (L3, 설계 §7):
```
episodes 1행 → scenes N행 → entities upsert(이름/별칭 = lexicon 대조) → observations · events · relations · rules (observed)
→ coverage → (카드는 계산만) → 화면
```

## 2. 화면 와이어 텍스트

글자만으로 그린다. 위치·크기는 구현 때 train 컴포넌트 규약을 따른다(`app/setting/`).

### 2-1. 작품 뷰 `/setting/[work]`

```
┌ 탑을 오르는 법 (연재 2화)                                   [회차 투입 +]  [내보내기 ▾]
├ 인물 7 · 조직 3 · 지명 1 · 구조물 1 · 용어·스킬·물건·종족 6 · 규칙 4 · 시간선 2갈래   확인 필요 2
│
│  [인물] [지명] [용어] [규칙] [시간선]  |  [확인 필요 ●2]
│
│  인물
│   유진혁 (진혁)         첫 1화 · 최근 2화     나이 19|20→22 ⚠ · 소속 베나토르 · 스킬 질풍 (←쾌속 ⚠)
│   김수정 (수정)         첫 1화 · 최근 1화     생사 사망 [회귀 전]
│   마강혁                첫 2화                소속 종로경찰서 · 직업 형사
│   …
│  회색 = 관찰(observed). 검정 = 정본(canonical). ⚠ = 이 개체에 확인 필요 카드가 있다.
└
```

- 검사 결과 탭은 없다. **확인 필요 = 검사 결과.** 카드 수는 요청 때 계산한다(저장 안 함).
- `[회차 투입 +]` 는 붙여넣기 한 칸. 투입 → 추출(MEDIUM·3회·합집합, 마개 뒤) → 저장 → 이 화면으로 돌아오며 "관찰 새 값 M · 확인 필요 N · 시간 미확정 장면 K" 한 줄.

### 2-2. 개체 페이지 `/setting/[work]/entity/[id]`

```
┌ 유진혁   별칭 진혁 · character · 첫 등장 1화 · 최근 2화              회차 [1 ───●─── 2]  갈래 [main ▾]
│
│  지금 상태 (2화 기준)
│   나이     22            [원문] "스물두 살 인생에"                     support 3/3
│   소속     베나토르        [원문] "저희 팀의 일원이 되어주십쇼"  (사건에서)    support 3/3
│   스킬     질풍 (유일)     [원문] "스킬 질풍을 실험" · "내가 가진 유일한 스킬이다"   support 3/3
│            쾌속 (1화)      [원문] "스킬 쾌속을 얻으셨습니다"                support 3/3
│   …
│   회색 값 = 관찰. [정본으로] 를 누르면 검정이 되고 canonical 에 구간이 생긴다(from_ep = 이 회차).
│
│  바뀐 것
│   1화  나이 19|20   →  2화 22        ⚠ 전이 사건 없음        [원문] [원문]   → 확인 필요 #1
│   1화  스킬 쾌속    →  2화 질풍(유일) ⚠ 개명·상실 사건 없음    [원문] [원문]   → 확인 필요 #2
│
│  관계      김수정 — 첫눈에 반한 대상 (1화)   ·   베나토르 — 팀의 일원으로 합류 (2화)
│  규칙      (이 개체에 걸린 규칙 없음)
│  메모      (분류 안 됨) 중학교 때부터 배워온 복싱 · 위기를 생각보다 즐기는 성격      [개체 메모로 확정] [지우기]
│
│  확인 필요 2
└
```

- **회차 슬라이더**: 슬라이더를 1화로 두면 "지금 상태" 가 1화 시점으로 바뀐다 — canonical 은 구간으로, observations 는 `episode <= 슬라이더` 중 마지막 값으로. 한계 문서 7번.
- **갈래 선택**: 갈래가 둘 이상인 개체(김수정: main / pre_regression)만 활성. 기본은 main.
- `[원문]` 은 원고 뷰어의 그 오프셋으로 점프(span). 회차 슬라이더와 무관하게 항상 원문이 옆에 있다(원칙 4).
- support 는 합집합 등장 횟수. 1/N 은 값 옆에 "약함" 배지 — 회색보다 더 옅게.
- **인라인 편집**: 값 클릭 → 입력 → 저장. 저장은 canonical 행 insert(`source = author_ui`) 이지 관찰 수정이 아니다(관찰은 불변).
- **자유 서술 칸**(§5-3): 페이지 아래 "그냥 글로 쓰기" 한 칸. 저장 시 추출 파이프라인을 태워 상태·관계·규칙으로 나누고, 못 나눈 부분은 메모. 2단계에서는 칸만 두고 파이프라인 연결은 3단계(메모 import)와 같이.

### 2-3. 확인 필요 카드 `/setting/[work]/review`

```
┌ 확인 필요 2   (약함 0)                                  [약한 카드도 보기 □]
│
│ #1  유진혁 · 나이     1화 19|20  →  2화 22     사이에 나이를 바꾸는 사건이 없다
│      [원문] "생일도 지난 나이라 합법적으로"        [원문] "스물두 살 인생에"
│      힌트: 만 나이/세는 나이 차이일 수 있음 (19|20 가 같은 문장에서 두 값)
│      ( 사건 등록: 시간 도약 ___년 후 )  ( 규칙 등록: 이 작품은 세는 나이 )  ( 2화 원고 수정 )  ( 무시 )
│
│ #2  유진혁 · 스킬     1화 쾌속  →  2화 질풍(유일)   쾌속을 없앤 사건도, 개명 사건도 없다
│      [원문] "스킬 쾌속을 얻으셨습니다"            [원문] "내가 가진 유일한 스킬이다"
│      ( 사건 등록: 개명 쾌속→질풍 )  ( 별칭 등록: 질풍 = 쾌속 )  ( 2화 원고 수정 )  ( 무시 )
│
│  결정한 것 (되돌리기 가능)
│   —
└
```

- 카드 = `detectStateChangeWithoutEvent(observations, events, decisions)`. 결정이 있으면 그 dismiss_key 는 안 나온다.
- 버튼 하나 = decisions 1행(+ 필요하면 events/rules/lexicon 1행, `payload` 에 그 id). "되돌리기" = 그 행들 삭제.
- 같은 카드는 다시 묻지 않는다(한계 문서 5번). 카드가 순수 함수라서 가능하다 — 저장했으면 결정 뒤에 낡은 카드가 남는다(리뷰 F).
- 약한 카드(weak): 대사 속 타인 주장 · 둘 다 inferred · 숫자화 실패 · support 1/N. 기본은 접고 스위치로 편다.

### 2-4. 없는 것 (일부러)

- "이상 없음" 화면. 카드 0 이면 "확인 필요 0 · 시간 미확정 장면 K · 분류 안 됨 M" 을 그대로 보인다(원칙 5).
- 자동 승격. 회차를 아무리 넣어도 canonical 은 작가가 누르기 전엔 비어 있다(원칙 7).
- 카드 테이블 · 검사 결과 탭.

## 3. decisions 의 액션과 부수 효과

| action | 만드는 행 | 되돌리기 |
|---|---|---|
| `dismiss` | decisions 1 | decisions 삭제 |
| `register_event` | events 1 (`source=author_ui`, subject·attribute·before·after) + decisions 1 (payload.event_id) | 둘 다 삭제 |
| `register_rule` | rules 1 (`source=author_ui`, 예: 나이 체계 = 세는 나이) + decisions 1 | 둘 다 삭제 |
| `register_alias` | lexicon 1 (is_alias, 같은 entity_id) + decisions 1. 이후 추출의 `{{lexicon}}` 에 들어간다 | 둘 다 삭제 |
| `fix_manuscript` | decisions 1 (payload.episode, span). 원고를 고치면 재추출로 관찰이 바뀐다 | decisions 삭제 |

카드 키는 값 쌍을 정렬한 `makeDismissKey(entity, attribute_key, v1, v2)` — 순서 무관(P6). **entity 는 관찰의 임시 id 가 아니라 `entities.id`** 여야 회차를 다시 넣어도 키가 같다. 1단계 verify 의 `ent_0` 같은 위치 id 는 여기서 끝난다.

## 4. 2단계 완료 기준 (설계 §11)

1. 회차 1·2화를 투입하면 위 화면 셋이 관찰로 채워진다(합집합, support 표시).
2. 확인 필요 카드 2장(나이·스킬)이 뜨고, 버튼 하나로 결정이 저장되며, 되돌리기가 동작한다.
3. 카드 = 순수 함수 확인: decisions 를 지우면 카드가 그대로 돌아온다. DB 에 카드 행은 없다.
4. 회차 슬라이더를 1화로 두면 유진혁 나이가 19|20, 스킬이 쾌속으로 보인다.
5. 물기 시험: 승격·결정·되돌리기를 순수 함수(저장소 어댑터 위)로 떼어 verify 에 붙인다. 빈 결과를 통과로 읽지 않는다.

## 5. 열린 질문 (박 님 결정)

1. 편집자(work_members.editor)가 정본을 고칠 수 있는가, 코멘트만인가. — 초안 SQL 은 editor 에 쓰기를 줬다.
2. 회차 투입 시 3회 호출 비용(회차당 ~$0.06)을 사용자 한도(`consume_ai_quota`)에 어떻게 셀지 — 회차 1 = 호출 3 으로 세는 게 단순하다.
3. `scenes.work_id` 중복 컬럼(RLS 단순화) — SQL 초안 Q3.
4. `app/setting/` 를 train 라우트 그룹과 같은 레이아웃에 둘지 별도 레이아웃인지.
