## 0. 작업 환경

### 0-1. Kiwi를 먼저 깔아라

세션 2·3의 생산성은 대부분 여기서 나왔다. 컨테이너에 형태소 분석기를 설치하면
문항의 부사·관형형·동사·표제어를 **직접 측정**할 수 있다. 초안을 주고 사용자가

```bash
pip install kiwipiepy --break-system-packages
```

`main.py`의 집계 규칙을 그대로 재현한 스크립트를 만들어 쓴다.

- 부사 = MAG/MAJ + `-게` 부사형 (단, MAG 뒤 인접 XSA 제외, `-게 되다` 제외)
- 관형형 = ETM/MM, 지시관형사 제외
- 동사 = VV\* + NNG+XSV
- 반복 = 표제어 기준
- 표제어(lemmas) = NNG/NNP/VV/VA/MAG/XR, surface는 어절 전체

### 0-2. 저장소는 기본 비공개다 ★

`https://github.com/park-jang-sup/novel-trainer`

**평소 private이다.** 세션을 시작할 때 사용자가 public으로 열고, 어시스턴트가
코드를 다 읽은 뒤 다시 닫는다. "항상 열어둔다"도 "항상 닫아둔다"도 아니다.
필요할 때만 연다.

**절차**

1. 사용자가 GitHub에서 public으로 전환한다
   (Settings → General → Danger Zone → Change visibility)
2. 사용자가 "열었다"고 알린다
3. 어시스턴트가 즉시 클론한다

   ```bash
   git clone --depth 50 https://github.com/park-jang-sup/novel-trainer.git
   ```

4. 어시스턴트가 **필요한 파일을 한 번에 다 읽고** "다 읽었다"고 알린다
5. 사용자가 다시 private으로 닫는다

**어시스턴트의 책임: 열려 있는 동안 다 읽어라.**
닫힌 뒤에 "그 파일 좀 더 보고 싶다"고 하면 사용자가 다시 열어야 한다.
클론본은 세션 안에서 계속 남아 있으므로 한 번 받아두면 저장소가 닫혀도
읽는 데 지장이 없다. **나중에 필요할 것 같은 파일까지 미리 받아라.**
세션 3에서 초반에 클론해둔 덕에 `TrainClient.tsx`·`Editor.tsx`·`local.ts`를
한참 뒤에 필요할 때 바로 읽을 수 있었다.

**여는 이유**: `seed_all.sql`에 스키마·시드·불변식이 전부 있어 이것만 읽으면
컬럼명을 물어보지 않아도 된다. 세션 2에서 "컬럼명을 알려달라"고 요청한 것은
저장소를 읽지 않아서 생긴 낭비였다.

**닫는 이유**: `seed_all.sql`에 `forbidWords` 전량과 14단계 선택형 정답 인덱스가
평문으로 들어 있다. 정답 4개는 이미 public 이력이 남았고 되돌릴 수 없다(8장).

## 2. 세션 2 요약 — 이어받을 것

### 2-1. `maxAdverbs`는 1을 유지한다 ★

세션 2에서 2로 올리자고 제안했다가 **철회했다.** 근거가 "형태소 분석기가
부사를 오탐하므로 예산에 여유가 필요하다"였는데, 이것은 **버그를 예산으로
덮자는 주장**이고 두 축을 섞은 것이다.

- 교육적으로 1이 옳은가 — 별개 문제
- 채점기가 오탐을 내는가 — 별개 문제

1은 실수가 아니라 의도다. **동사만으로 써보게 하는 극단 제약**이 1단계의
목적이고, 원 강의 5번이 그 근거다. 오탐은 계산기를 고쳐서 없앤다.

측정: `maxAdverbs` 3이면 **부사 3개를 그대로 둔 채 길이만 줄인 답안이
4문항 전부 통과**한다. `maxChars`만으로는 부사를 걷어내게 만들지 못한다.

세션 3에서 1단계 지시문 8개에 이 한 줄을 넣었다(DB 반영 완료).

> 여기서는 일부러 부사를 전부 막습니다. 실제 소설에서는 쓰셔도 됩니다 —
> 언제 쓰는지는 뒤에서 다룹니다.

### 2-2. 문항 설계 원칙 — 규격서 3장에 넣을 것 ★

**(가) 모범답안이 통과하는지만 봐서는 부족하다.**
규격서 6번은 모범답안 통과 확인만 요구하는데 그것만으로는 뚫린다.
3단계 초안은 모범답안이 8/8 통과했는데도 **절반이 뚫려** 있었다.
반드시 **"지시대로 하지 않은 답안"이 실제로 미달인지** 함께 확인한다.

**(나) 검사 항목의 방향이 단계 목적과 맞아야 한다.**
3단계와 4단계는 같은 `maxChars`인데 정반대로 작용한다.

| | 3단계 군더더기 빼기 | 4단계 반복 표현 제거 |
|---|---|---|
| `maxChars` | **조인다** (원문의 53~58%) | **푼다** (모범답안 + 3) |
| 이유 | 조이지 않으면 걷어내지 않는다 | 조이면 반복 문장을 통째로 지우는 게 정답이 된다 |
| `minVerbs` | 모범답안 동사 − 1 | 원문 동사 수 가까이 |
| 막는 것 | 핵심을 지우고 군더더기를 남긴 답안 | 반복 문장을 삭제한 답안 |

**(다) 3단계 지문의 군더더기 문장은 동사 없이 쓴다.**
서술격·형용사로만 쓴다. 그래야 군더더기만 남긴 답안이 동사 0개가 되어
`minVerbs`에 걸린다. 초안에서 군더더기에 동사를 섞었더니 8문항 중 4문항이 뚫렸다.

### 2-3. 판정을 세 층으로 나눈다

| 층 | 대상 | 근거 |
|---|---|---|
| 실패로 막는다 | 표제어 반복, 글자 수 | 오탐이 확인되지 않음 |
| 경고만 띄운다 | 오탐 가능한 것 | 진도는 막지 않는다 |
| 조용히 넘긴다 | 확신 없는 전부 | |

**오탐 두 종류는 비용이 다르다.** 놓치고 통과시키면 학습자는 모른다.
멀쩡한 문장을 잡으면 그 자리에서 신뢰가 끝난다. 후자를 0에 수렴시키는 것이
설계 목표다.

**닫힌 목록으로 만들면 오탐의 상한이 목록 크기로 고정된다.**
손으로 검증한 20개만 넣으면 오탐이 발생할 수 있는 경우의 수가 20개뿐이다.
"시각을 뜻하는 단어를 탐지"하는 열린 방식은 오탐의 상한이 없다.

**이의제기 버튼을 붙인다.** 오탐을 만난 학습자에게 출구가 생기고, 동시에
목록을 깎을 데이터가 모인다. `golden_cases`가 7행뿐인 결핍을 메워준다.
근거 표시(하이라이트)는 이미 구현돼 있다. **아직 미착수.**

세션 3의 조정: 6단계 시각어는 **경고가 아니라 실패**로 갔다. 3층 구조가
틀린 게 아니라, **지시문에 규칙으로 선언하면 오탐이 아니라 제약이 되어
1층으로 올라간다**(4-6).

## 3. 정정된 것 ★

### 3-1. 세션 2: "부사 오탐 수정은 대기 중"은 사실이 아니었다

세션 2 문서가 이를 미실행으로 적었으나, 로컬 `main.py`에 수정 A·B가

미루면 다음 세션이 저장소를 근거로 삼아 이미 끝난 일을 다시 시킨다.

### 3-2. 세션 2: "패치가 부사 여유를 완화한다"는 틀렸다

세션 2의 5-3 마지막 줄이 `heungbu-joy`와 `gyeonu-longing`의 여유가 패치로
완화된다고 적었다. 재측정 결과:

```
heungbu-joy       부사 1  ['도로']
gyeonu-longing    부사 1  ['다시']
rm-kongjwi-jar    부사 1  ['다시']
```

전부 정탐이다. 수정 A는 MAG 뒤 인접 XSA만, 수정 B는 `-게 되다`만 걷어낸다.
여유 0인 답안은 두 건이 아니라 **세 건**이고 패치와 무관하게 그대로다.
여유를 원하면 답안을 다시 쓰는 수밖에 없다. **상한은 건드리지 않는다.**

교훈: **예측을 문서에 적을 때는 재고 나서 적는다.**

### 3-3. 세션 2: 8번은 '동사 중심'이 아니라 예외 묶음이다

세션 2가 8번을 1·3과 함께 동사 중심에 넣었다. 원문은 이렇다.

> 8. 동사로 연출을 하고, 형용사 부사로 꾸며주는 말이다.
>    (어떤 행동을 하다(동사) 호기롭게 하다(부사))

부사를 줄이라는 말이 아니라 **부사의 정당한 직무를 정의하는 문장**이다.
6번이 "언제 써도 되는가", 8번은 "어떻게 써야 정당한가"를 말한다.
5단계 문항 3·4의 판정 근거가 정확히 이것이다.

세션 2의 "8번 자동 판정은 회의적"은 **유지한다.** 자유서술로 채점하자는 게
아니라 선택형 정답 근거로만 쓴다.

### 3-4. 세션 2: 9번에는 실질 내용이 없다

> 9. 물론 상황에 따라 사용하는 경우가 있다.

한 줄이고 5·6의 재진술이다. 문항 근거로 삼을 게 없어 설명문에 흡수했다.

### 3-5. 세션 2: `눈`에 대한 판단을 뒤집었다

세션 2의 3-3은 `눈/NNG`를 목록에 넣지 않기로 했다. 眼과 雪이 같은 표제어라
갈라지지 않고, **"재현율보다 정밀도"**라는 원칙에 따른 것이었다.

세션 3에서 **뒤집었다.** 문자열 `눈`을 `forbidWords`에 넣었다. 이유:

- 6단계는 시각 차단이 목적인데 `눈앞`·`눈에 띄다`가 통과하면 단계가 무의미하다.
  실제로 우회 시도 10건 중 8건이 통과했다(4-2)
- **`눈`이 들어간 말을 전부 막는다고 지시문에 선언**하면 오탐이 아니라 규칙이 된다.
  `눈물`·`눈치`도 걸리지만 학습자가 알고 들어간다
- 6단계 지문에 눈(雪) 장면을 넣지 않으면 실질 충돌이 없다

정밀도 원칙 자체는 유효하다. **다만 "규칙으로 선언할 수 있는가"라는 세 번째
선택지가 있다.** 문맥으로 가릴 수 없으면 미리 알리는 쪽이 낫다(4-6).

### 3-6. 세션 3: `stage_id`는 uuid가 아니라 정수다

"애플리케이션은 `stageId`(uuid)로 라우팅한다"고 적었으나 정수다.
`order_no` 재배치가 안전하다는 판단 자체는 유효하다 — 요점은 "라우팅이
`order_no`가 아니라 `id`를 쓴다"였고 `id`는 안 바뀌었다.

### 3-7. 세션 3: `검/VA`을 뺀 것은 근거 없는 판단이었다

6단계 금지 목록에서 `검/VA`을 "오탐 여지"로 뺐다. 재보니 오탐이 없었다.

```
칼을 검으로 막았다  → 검/NNG
검사가 들어왔다     → 검사/NNG
자료를 검토했다     → 검토/NNG
까치들의 검은 모습  → 검/VA
```

**표제어 매칭은 태그로 갈리므로 문자열 매칭의 동음이의 걱정이 통하지 않는다.**
문자열 시절의 감각으로 판단한 것이다. `검/VA`·`노랗/VA`·`누렇/VA`를 추가했다.

빼기 전에는 `sn-gyeonu-bridge` 지문의 `검은`이 **자기 금지 목록을 통과하고**
있었다. **지문이 자기 검사에 걸리는지 반드시 확인할 것.**

### 3-8. 세션 3: 지시문 길이는 문제가 아니었다

여덟 문항의 지시문이 같은 문장으로 끝나는 것을 걷어내자고 제안했으나,
사용자가 실물 화면을 보고 그대로 두기로 했다. 화면에서 지시문은 위, 원문은
상자 안이라 위계가 이미 갈려 있다.

교훈: **화면 문제는 화면을 보고 판단한다.** 글자 수로 추정하지 않는다.

## 4. 세션 3의 결정과 근거

### 4-1. 선택형은 표면 지표로 정답이 새면 안 된다 ★ 규격서 3장에 넣을 것

5단계 초안에서 정답이 항상 부사 최소 개수 쪽이었다.

| 문항 | 정답 | 오답 |
|---|---|---|
| 견우 | 1개 | 1 / 2 / 2 |
| 토끼 | 1개 | 1 / 2 / 2 |
| 나무꾼 | 1개 | 1 / 2 / 2 |

1단계를 막 마친 학습자는 "부사가 적을수록 좋다"를 학습한 상태로 온다.
내용을 안 읽고 개수만 세어도 좁혀지고 **이 단계의 목적과 반대 신호를 준다.**

수정: 문항마다 정답과 같은 개수의 오답을 최소 하나 둔다.

```
견우   0 / 1(정답) / 1 / 2
토끼   1(정답) / 0 / 2 / 1
나무꾼 1(정답) / 1 / 2 / 0
콩쥐   1 / 1 / 1(정답) / 2
```

**일반화**: 2-2 (가)는 자유서술용 검사였다. 선택형에는 대응하는 검사가
없었다. 이제 있다 — **정답을 세는 것만으로 맞힐 수 있는 표면 지표가 있는지
확인한다.** 글자 수, 문장 수, 부사 수, 선택지 길이가 모두 후보다.

### 4-2. `forbidLemmas`는 `forbidWords`를 대체하지 않는다 ★

세션 2의 3-4는 대체를 전제했다. **병용이 맞다.** 둘 다 측정으로 확인했다.

문자열이 활용형을 놓친다:

```
'쳐다봤다'는 '쳐다보'를 포함하지 않는다
'봤다'는 '보'를 포함하지 않는다
시각 어휘 8문장에 stem을 걸어보니 '보'가 2/8밖에 못 잡았다
```

표제어가 복합어를 놓친다:

```
'눈앞'은 눈앞/NNG 한 덩어리라 눈/NNG로 안 잡힌다
'물빛'은 물빛/NNG 한 덩어리라 빛/NNG로 안 잡힌다
```

| 검사 | 잡는 것 | 못 잡는 것 |
|---|---|---|
| `forbidLemmas` | 활용형 | 복합어 |
| `forbidWords` | 복합어 | 활용형 |

병용 전에는 우회 시도 10건 중 **8건이 통과**했다. 병용 후 10/10 검출,
모범답안 8건 오탐 0건.

**뜻밖의 이득**: `forbidWords`는 `gradeLocal`에서 형태소 없이 즉시 판정된다.
형태소 서버가 죽어도 시각 복합어는 그대로 잡힌다. 하나로 합쳤다면 전부
대기가 됐을 자리다.

### 4-3. 판정은 나누고 화면에서만 합친다

사용자 판단: **시스템 설계에서 가장 중요한 것은 정확성이다.**

- `combine()` 출력은 두 Check를 끝까지 분리 유지한다. DB에 그대로 저장된다.
  병합본이 저장되면 나중에 어느 검사가 걸렸는지 되짚을 수 없다
- 병합은 `mergeForbidChecks` 순수 함수로 화면 직전에만 건다
- **합친 key를 `forbidWords`로 유지한다.** `Editor.tsx`의 `markClassFor`가
  key로 하이라이트 색을 고르므로 새 key를 만들면 밑줄이 안 붙는다
- **fail이 pending보다 우선한다.** 형태소 서버가 죽어 `forbidLemmas`가
  pending이어도 `forbidWords`가 이미 찾은 미달은 감춰지면 안 된다
- `TrainClient`에서 `useMemo`로 한 번만 계산해 `Editor`와 결과 목록 양쪽에
  넘긴다. 각각 부르면 하이라이트와 목록이 갈라진다

화면 확인: 한 줄 4개(`눈앞에`·`모습이`·`검은`·`내려다보았다`), 네 개 전부 밑줄.

### 4-4. 원 강의 5번은 문항 근거가 아니라 오답 선택지다

| 원칙 | 요지 | 처리 |
|---|---|---|
| 5 | 동사만으로는 불가능, 습작용 | **오답 선택지로 편입** |
| 6 | 앞에서 언급했으면 중후반에 써도 된다 | 판정 근거 (문항 1·2) |
| 8 | 동사로 연출하고 형용사·부사로 꾸민다 | 판정 근거 (문항 3·4) |
| 9 | 상황에 따라 쓰는 경우가 있다 | 설명문으로 흡수 |

5번을 문항으로 만들려다 접었다. 부사 0개로도 좋은 문장이 얼마든지 써지므로
"동사만으로는 불가능"을 선택형으로 증명하려 들면 뚫린다.
대신 각 문항의 **'부사 0개' 오답**이 5번을 담는다. 앞 문장이 다 깔려 있는데도
부사를 비우면 태도가 사라진다는 것을 그 자리에서 보게 한다.

### 4-5. 5단계 배치는 4단계 뒤

원 강의가 1~4(원칙) → 5·6(예외) 순이고 커리큘럼 1~4단계가 원칙 넷을 담는다.

`order_no`는 **애플리케이션 코드 어디에서도 참조되지 않는다** —
`seed_all.sql`의 insert와 주석 처리된 불변식 쿼리 두 곳뿐이다.

유니크 제약 여부가 불확실해 **+100 후 -99의 2단계**로 밀었다. 단일 +1
업데이트는 비지연 유니크 인덱스가 있으면 문 중간에 충돌할 수 있다.

### 4-6. 오탐은 규칙으로 선언한다 ★

- 5단계: `보/VV`는 "맛을 보다"도 잡는다
- 6단계: `forbidWords` `눈`은 어절 전체를 잡으므로 `눈물`·`눈치`도 걸린다

**문맥으로 가리려 하지 않는다.** 채점기는 구문을 모른다. 사전과 규칙으로
조사를 떼려다 오탐만 만든 전례가 `local.ts:41`에 적혀 있다.

대신 **지시문에 미리 선언한다.** 1단계 부사 전면 금지와 같은 구조다.
오탐이 아니라 극단 제약이고, 학습자가 알고 들어간다.
이것이 2-3의 3층 구조에 없던 **네 번째 선택지**다.

### 4-7. 6단계는 장면 설정을 `instruction`에 둔다

설정을 `passage`에 넣으면 학습자가 그대로 베껴도 통과한다.
`passage`에는 걷어낼 대상만 남긴다.

### 4-8. 단계를 더 늘리지 않는다 — 병목은 문항 수다 ★

작법 문서에서 후보를 여섯 개 건졌으나 이번에 만든 것은 하나뿐이다.
53문항 / 148, 36%. 24개 단계 중 14개가 비어 있다.
여섯 개를 더하면 목표가 172로 올라가고 채움률이 31%로 **떨어진다.**

처음 시작하는 작가에게 힘이 되는 것은 단계 목록의 길이가 아니라
**끊기지 않고 끝까지 가는 경로가 하나 있는 것**이다.

## 5. 확인한 사실 — 다시 재지 말 것

### 5-1. Kiwi 태깅

**보조용언은 VV와 갈린다.**

| 입력 | 결과 |
|---|---|
| 밥을 먹어 보았다 / 한번 해 봤다 / 문을 열어 봤다 | `보/VX` |
| 그는 하늘을 보았다 / 창밖을 봤다 / 맛을 보았다 | `보/VV` |

이게 안 갈렸으면 `보/VV`는 금지 목록에 못 넣을 뻔했다.

**표제어 매칭은 접두사 충돌이 없다.**
`보이/VV`·`바라보/VV`·`쳐다보/VV`를 막아도 `보리`·`보름달`·`보물`·`보자기`·
`보내`는 안 걸린다. 태그로 갈리므로 `검/VA`과 `검사/NNG`도 갈린다.

**ㅂ불규칙은 한 표제어로 모인다.**
`그리웠다`·`그리워서`·`그리운`·`그립다` → 전부 `그립/VA-I`.
따라서 **태그는 반드시 접두 비교**한다. `=== 'VA'`로는 `VA-I`가 영원히 안 걸린다.

**`눈`은 표제어로 갈라지지 않는다. 조사로 갈린다.**
`눈에 들어왔다`(眼)는 `에/JKB`, `눈이 내렸다`(雪)는 `이/JKS`.
연어 3연쇄로는 구분 가능하나 쓰지 않기로 했다(3-5).

**`-게 되다`의 `되`는 VV다.**
`조용하/VA[4:7] + 게/EC[7:8] + 되/VV[9:10]`. VX였으면 수정 B가 발화하지 않았다.

**`MAG + XSA` 인접 여부로 어근과 부사가 갈린다.**

| 입력 | 태깅 | 판정 |
|---|---|---|
| 캄캄했다 | `캄캄/MAG[2:4]` + `하/XSA[4:5]` | 붙어 있음 → 부사 아님 |
| 천천히 했다 | `천천히/MAG[0:3]` + `하/VV[4:5]` | 떨어져 있음 → 부사 맞음 |

**부사 세기에는 오탐이 있었고 반복 세기에는 없다.**
"품사 태깅은 의미 판정이 아니므로 중의성이 없다"는 명제는 부사에서
성립하지 않는다. 품사 태깅 자체가 흔들린다.

### 5-2. `lemmas`의 어절 되짚기는 겹침을 허용한다

Claude Code가 `end == start` 대신 **`다음 시작 <= 앞 끝`**으로 완화했다.
`봤 = 보+았`처럼 형태소 구간이 겹치기 때문이다.
까다로운 문장 10개로 시뮬레이션한 결과 **어절 경계를 넘은 건 0건**이다.
공백이 있으면 `start > end`가 되므로 구조적으로 안전하다.
문장부호(S로 시작하는 태그)는 간격이 없어도 어절 밖으로 취급한다.

**`surface`는 어절 전체다.** `조심스럽게`의 `조심/NNG`는 surface가
`조심스럽게`다. 근거를 화면에 뿌릴 때 표제어와 표시가 다를 수 있다.

**표면형은 반드시 `text[start:end]`로 자른다.** `len(form)`으로 계산하면
불규칙 활용에서 깨진다. `차가운`의 VA-I 토큰은 form이 `차갑`(2자)인데
표면 길이는 3이다.

### 5-3. DB 권한 설계는 잘 잡혀 있다

| 테이블 | RLS | 정책 | anon | authenticated | service_role |
|---|---|---|---|---|---|
| `stages` | ○ | authed read stages | ✗ | SELECT | ✗ |
| `problems` | ○ | authed read problems | ✗ | SELECT | ✗ |
| `problem_answers` | ○ | 없음 | ✗ | ✗ | SELECT |
| `golden_cases` | ○ | 없음 | ✗ | ✗ | SELECT |

정책 없음 + RLS 켜짐 = 아무도 못 읽음. `service_role`은 RLS를 우회한다.
**`anon`은 어디에도 닿지 못한다.** `relforcerowsecurity=false`도 정상이다
(소유자에게 RLS를 적용할지의 스위치. 마이그레이션 주체라 막으면 곤란하다).

**Supabase 에디터가 `problems`를 건드리는 쿼리에 "RLS 없이 테이블 생성"
경고를 띄우는데 오탐이다.** `Run without RLS`로 실행하면 된다.

**RLS를 끄거나 켜려 하지 마라.** 정책 없이 켜면 `authenticated` 읽기가
전부 차단돼 53문항이 화면에서 사라진다.

### 5-4. `publicConfig` 필터는 정상 작동한다

`app/train/[stageId]/page.tsx`가 `maxChars`·`cards`·`count`·`minLen`·
`maxLen`·`inputs`만 넘기고 `forbidWords`·`maxAdverbs`·`minVerbs`·
`maxRepeat`는 걸러낸다.

**다만 RLS는 컬럼을 못 거른다.** `authenticated`가 `problems`를 직접 읽으면
`scoring_config` 전체가 보인다. 앱 경로는 막혔고 DB 경로는 열려 있다(8장).

### 5-5. 형태소 서버가 죽으면 pending이고 통과되지 않는다

`combine()`이 `morph`가 없으면 `pendingMorphChecks`를 넣고 `status`는
`pending`이다. `needsAi`는 `status === 'pass'`를 요구하므로 AI도 안 불린다.

### 5-6. `selftest.py`의 로컬 경로와 HTTP 경로는 다르다

`resolve_local()`은 얇은 어댑터를 거치고 HTTP는 FastAPI 핸들러를 직접 탄다.
**로컬 통과가 HTTP 통과를 보증하지 않는다.** 둘 다 돌릴 것.

```bash
cd ~/projects/novel-trainer/scoring-server && source .venv/bin/activate
SCORING_SECRET=dev python3 selftest.py
SCORING_SECRET=dev uvicorn main:app --port 8000 &
sleep 3
SCORING_SECRET=dev python3 selftest.py --http
kill %1
```

`main.py`가 임포트 시점에 `os.environ["SCORING_SECRET"]`을 요구한다.
없으면 KeyError로 죽는다.

### 5-7. 배열 설정과 수치 설정의 가드가 다르다

```
수치 상한(maxAdverbs 등)  → cfg.X !== undefined
배열(forbidWords 등)      → cfg.X?.length
```

빈 배열은 "검사 켬"이 아니다. `morph.ts`와 `local.ts`에서 **같은 가드**를
써야 한다. 다르면 pending 없이 결과만 튀어나온다.

### 6-2. 6단계 모범답안

## 7. 작법 문서 7종 융합 방침

프로젝트 지식의 작법강의 3종 + 작법정리 4종을 커리큘럼에 녹이는 기준.

### 7-1. 판별 기준 — 3층

| 층 | 조건 | 처리 |
|---|---|---|
| 훈련 단계 | 형태소·문자열로 ○×가 갈린다 | 단계로 만든다 |
| 진단 문항 | 정답이 하나로 정해지는 선택형이 된다 | 선택형으로 만든다 |
| 레슨 설명문 | 위 둘이 안 된다 | **단계로 만들지 않는다** |

두 번째 필터: **초보가 실제로 틀리는 것만.** 7종의 상당 부분(계약, 유료 전환,
공모전, 스크리브너, 멘탈, 인터뷰)은 계약 단계 작가용이라 훈련 대상이 아니다.

### 7-2. 자동 판정이 되는 것 셋 (미착수)

**(가) 개행 밀도** — `02강의 [SE-01]`
웹소설은 문단을 많이 띄운다, 가독성이 제일 중요하다, "남성향 하시는 분들은
좀 힘들어한다". **순수 문자열 계산.** 형태소도 AI도 필요 없다.
24단계에 없고 소설 일반이 아니라 **웹소설 고유**의 규칙이다.

**(나) 등장인물 수 제한** — `작법정리 2부 18-3`
"1화에 고유명사 네 개 이상 나오면 안 된다"는 수치가 원문에 있다.
`maxProperNouns`로 **구현 완료**(`ebbdc96`). 다만 **아직 어느 문항에도 얹지
않았다.** 측정 확인:

```
'흥부는 마당에 나갔다. 놀부와 심청이 견우를 데리고 왔다.'
  → NNP ['흥부','놀부','심청','견우']  4개
```

**(다) 종결어미 다양화** — `02강의 [SE-03]`
"끝이 매번 ~했다로 가면 지루하다." **모범답안이 전부 100% `-았/었다`다.**
4단계(어휘 반복 `repeats`)와 다른 축이다. `EP`+`EF` 조합으로 잰다.
**함정**: 표면형 잘라내기가 어렵다. 실측에서 `감쌌다`가 `쌌다`로 잘렸다
(어절 되짚기가 `감싸+았`에서 깨진다). 근거 하이라이트를 그 방식으로
만들면 안 된다.

### 7-3. 선택형으로 되는 것 둘

- **낙폭 구간 찾기** — `02강의 [IN-13]`. 9개 체크리스트가 원문에 표로 있다
  (개연성 구멍, 톤 붕괴, 방향성 흔들림, 의성어 남발, 독자에게 생각 강요 등).
  14단계 '궤도 이탈 찾기'와 형식은 같고 판단 기준이 다르다
- **개연성·현실성·핍진성 분류** — `02강의 [PS-05]`. 강의가 세 개념의 판단
  기준표를 직접 준다. 문장 하나를 주고 셋 중 무엇이 깨졌는지 고르게 하면
  정답이 하나로 떨어진다

### 7-4. 단계로 만들지 않는 것

제목, 소개글, 시놉시스, 로그라인, 공모전, 유료 전환, 계약, 멘탈, 자료조사,
스크리브너. 전부 자유서술이거나 채점 대상이 아니다.

**버리자는 뜻이 아니다.** 레슨 설명문과 예시로는 최고의 재료다.
"반만 보여줘라", "다섯 줄의 승부", "패턴은 독자와의 약속" 같은 문장은
훈련 화면 옆에 붙는 한 줄로 쓸 때 값이 있다.

### 7-5. 문항 지문의 원천으로 쓰는 법

작법 문서가 가장 크게 쓰이는 곳은 새 단계가 아니라 **빈 단계의 문항 지문**이다.
`작법정리 2부 2-1`의 실제 피드백 사례가 원문·모범답안 쌍이 된다.

> "빛이 거의 들어오지 않는 음습한 공간"
>   → "어두운 골목에 쓰레기통 사이로 쥐 한 마리가 몸을 숨긴 채 지켜보고 있었다"

단계를 새로 만드는 것보다 이쪽이 문서를 훨씬 잘 쓰는 길이다.

## 10. 사용자와의 작업 방식 — 반드시 지킬 것

### 10-1. 산출물 형태

| 종류 | 형태 |
|---|---|
| Claude Code에 줄 지시서 | **코드블록 안에 순수 텍스트.** md 파일로 만들지 않는다. 그대로 복사해 붙여넣을 수 있어야 한다 |
| 셸 명령 | 별도 코드블록. 사용자가 직접 실행 |
| SQL | 별도 코드블록. 사용자가 **Supabase SQL Editor에서 직접 실행.** 저장소에 파일로 넣지 않는다 |
| 설명·판단 | 채팅 본문 |

**코드는 직접 짜지 않고 Claude Code에 지시한다.** 리눅스 명령과 DB 입력은
사용자가 직접 한다. 지시서에 반드시 넣을 것:

```
DB 는 내가 직접 한다. psql 이나 supabase 명령을 실행하지 마라.
작업 후 변경 파일과 이유를 한 줄씩 요약하라.
```

건드리면 안 되는 디렉터리도 매번 명시한다.

### 10-2. 환경

- IntelliJ + WSL(Ubuntu). 셸 프롬프트는 `hse09@WIN-GNURBVDANTS`
- 저장소 경로 `~/projects/novel-trainer`
- Windows 다운로드 경로 `/mnt/c/Users/hse09/Downloads`
- 탐색기로 현재 폴더 열기는 `explorer.exe .`
- 파일을 전달할 때는 **먼저 파일로 만들어 넣게 하고, 그 다음 지시서를 돌리게
  한다.** 순서가 바뀌면 Claude Code가 파일을 새로 만들어버려 검증된 내용이
  날아간다

### 10-3. 대화 방식

**근거를 숫자로 요구한다.** "이게 나을 것 같다"는 통하지 않는다.
실제로 재서 보여줘야 한다.

**설계를 세운 뒤 반드시 뚫어본다.** 이 세션에서 값이 컸던 패턴은 전부 같은
형태였다 — 설계를 세우고, 그것이 **뚫리는지 직접 시험하고**, 뚫린 결과를
보여주고, 고치고, 다시 시험한다.

- 5단계 문항 초안은 부사 개수로 정답이 새고 있었다
- 6단계 금지 목록은 우회 시도 10건 중 8건이 통과했다
- 둘 다 재보지 않았으면 그대로 나갔다

**테스트가 초록불인 것으로 만족하지 않는다.** 잡아야 할 버그를 실제로 잡는지
확인한다. 세션 2에서 `selftest.py`를 만든 뒤 패치를 일부러 되돌려 빨간불이
뜨는지 확인했다.

**단위 테스트가 못 보는 구간이 있다.** `mergeForbidChecks`는 119건을
통과했지만 그 출력이 `Editor`를 지나 `markClassFor`를 통과해 밑줄이 되는
경로는 브라우저에서만 확인된다. **화면을 열어볼 것.**

**화면 문제는 화면을 보고 판단한다.** 지시문 길이를 글자 수로 추정해
걷어내자고 했으나 실물에서는 문제가 아니었다.

**문서를 그대로 믿지 않는다.** 세션 2의 "대기 중"과 "패치가 완화한다"가
둘 다 틀렸다. **코드와 실측이 문서보다 앞선다.**

**반박을 환영한다.** 사용자가 제안을 여러 번 뒤집었고 대체로 사용자가 옳았다.
`maxAdverbs` 건에서는 어시스턴트가 "버그를 예산으로 덮는" 제안을 했고
사용자가 잡아냈다. 동의할 수 없으면 그 자리에서 말하고, 틀렸으면 인정하고
이유를 문서에 남긴다.

**모르는 것은 모른다고 한다.** 추측으로 답하지 않고 자료를 요청한다.

**이모지·아이콘을 쓰지 않는다.** 프로젝트 디자인이 `○`·`×` 활자 기호를 쓴다.

**문서에 판단의 근거를 남긴다.** 이 프로젝트의 인수인계 문서는 결정만이 아니라
**왜 그렇게 결정했는지, 무엇을 시도했다가 접었는지**를 기록한다.
같은 함정을 두 번 밟지 않기 위해서다.
