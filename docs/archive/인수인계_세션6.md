## 2. 7단계 `rhythm` — 정체 확정

### 2-1. 무엇이 문제였나

세션 5까지 `stages.summary`가 `"문장 길이를 고르지 않게 배치한다"`였다. 세션 5 문서 7장이 "근거가 흔들린다"고 적었고, 세션 6이 확인했다.

### 2-2. 근거를 전수로 찾았다

작법 문서 7종을 `리듬 · 호흡 · 문장 길이 · 장문 · 단문 · 긴 문장 · 짧은 문장 · 개행 · 줄바꿈 · 문단`으로 전수 검색했다.

```
"문장 길이" "장문" "단문" "긴 문장"    →  4종 전부 0건
"리듬"                              →  연재 리듬(호흡) 1건. 문장 이야기가 아니다
```

**길이 배치는 근거가 0건이다.** 문서는 오히려 반대를 말한다.

> `웹소설_작법_정리.md:35` 설명·묘사보다 대화·독백 위주로 서술해 **짧은 문장 호흡을 유지**, 모바일 가독성 확보(문장마다 줄바꿈)

개행 쪽은 근거가 넷이다.

```
02강의:944   "보통 일반 소설에서는 절대 문단과 문단 사이를 뛰지 않는다.
              그런데 우리(웹소설)는 많이 뛴다."       ← 웹소설 고유 항목이다
02강의:945   "문장 하나에도 개행이 들어갈 수 있다"
              예: "그리고" / 개행 / "그는 그렇게 말했다"
02강의:946   "★ 이유: 웹소설은 가독성이 제일 중요한 장르이기 때문에"
              [SE-01] 은 24장 문장 설계 여섯 항목 중 유일한 ★★ 다
02강의:951   "한 번씩 그냥 뛰어주는 연습을 미리미리 해두면 좋다"
              ← 여섯 항목 중 강의가 직접 "연습"을 지시한 유일한 항목이다
정리:142     문장력을 기르는 법 (4) 문장 사이 적절한 개행으로 가독성 확보
```

### 2-3. 확정

```
skill_key   rhythm                       그대로
title       문장 리듬                     그대로 (웹소설에서 문장의 리듬은 길이가 아니라 개행이다)
summary     문단을 끊어 읽는 속도를 만든다   ← 고쳤다
```

### 2-4. 이때 정정한 것 — "완전 판정" 표현을 쓰지 마라

사용자가 "개행은 규칙으로 완전 판정되는 유일한 자리일 수 있다"고 제안했고, 세션 6이 정정했으며 사용자가 동의했다.

**배치는 규칙으로 판정된다. 내용은 아니다.** 분량 밴드 안에서 내용을 통째로 바꾼 답안은 규칙이 못 잡는다. 이건 서술형 문항 전부가 이미 안고 있는 것이지 이 단계의 성질이 아니다.

**"완전 판정된다"는 표현을 다음 문서에 쓰지 마라. 방패로 읽힌다.**

## 3. 검사 넷 — 무엇을 왜 넣었나

### 3-1. 최종 설계

`lib/scoring/types.ts`의 `ScoringConfig`에 넷을 더했다. **전부 순수 문자열이라 형태소 서버가 필요 없다.**

```ts
maxLineChars?: number       // 한 줄 최대 글자수. 공백 제외
minLines?: number           // 줄 수 하한
maxLines?: number           // 줄 수 상한
maxDuplicateLines?: number  // 중복 때문에 늘어난 줄 수의 상한
                            // = lines.length - new Set(lines).size
```

`lib/scoring/local.ts`의 `lineChecks()`에서 판정한다. **줄의 정의: `\n`으로 나눈 뒤 `trim`, 빈 줄 제외.** 빈 줄은 세지 않는다 — 문단 사이를 띄우는 관행을 벌하면 안 된다.

### 3-2. 폐기한 안 셋 — 왜 버렸는지가 중요하다

**A. 개행 수 하한만** (`min_line_breaks` 꼴)
→ 미검출 3건. 엔터 연타·두 글자마다·어절마다가 전부 통과한다.

**B. 줄당 글자수 하한** (`minLineChars`)
→ 오탐 1건. `[SE-01]:945`가 시범 보인 `"그리고"`(3자) 한 줄이 막힌다.
**단계 목적이 요구하는 답안을 막는 오탐은 지시문 선언으로 덮을 수 없다.** 세션 5의 4-1(`짙/VA`)과 같은 형태다.
→ 그래서 하한을 **줄 길이가 아니라 줄 개수**(`minLines`)에 걸었다.

**C. `distinctLines: true`** (모든 줄이 서로 달라야 한다)
→ 오탐 1건. `rh-axe-pond`를 문장마다 끊으면 `있었다.`가 두 문장의 꼬리로 각각 떨어져 같은 줄이 된다. 자연스러운 답안이 걸린다.

**C'. `maxSameLine: 2`** (같은 줄은 두 번까지)
→ 오탐은 사라지지만 미검출 4건. **앞 두 문장만 끊어 통째로 두 번 붙이면** 각 줄이 정확히 두 번씩만 나와서 줄마다 건 상한을 안 넘고, 분량은 절반 × 2 = 밴드 안이다.
→ 그래서 **줄마다가 아니라 답안 전체**에서 세는 `maxDuplicateLines`로 갔다.

```
자연스러운 꼬리 중복      1  →  통과
each-twice              4  →  검출
repeat-pair             6  →  검출
copy-short              7  →  검출
```

상한 `2`를 쓴다. 자연스러운 답안의 실측 최대가 1이라 여유 한 칸이 있고, 가장 약한 공격(4)과 두 칸 떨어져 있다.

### 3-3. 이름을 지을 때

저장소에 이미 있는 관례를 따른다. `distinctInitial`(`genre_coinage`), `maxRepeat`(`reduce_repeat`) 같은 것을 먼저 찾아본다. **다만 세는 대상이 다르면 이름도 달라야 한다** — `maxRepeat`는 한 단어가 몇 번이고 `maxDuplicateLines`는 답안 전체에서 몇 줄이다. `maxSameLine`이라 부르면 "한 줄이 두 번까지"로 읽히는데 실제 동작이 그게 아니라서 이름이 동작을 속인다.

## 4. 7단계 문항 8개

### 4-1. 밴드 — 여덟이 같다

```json
{"minChars":111,"maxChars":131,"maxLineChars":18,"minLines":7,"maxLines":13,
 "maxDuplicateLines":2,"requireAny":["<키워드>"]}
```

`type: 'convert'` · `scoring_mode: 'auto'` · `source_tag: 'folktale'`

**`type`을 `remove`로 넣으면 시드 전체가 롤백된다.** `seed_verify.sql` 불변식 1이 "`remove` 문항의 지문은 `maxChars`를 넘어야 한다"를 요구하는데 지문 115~127자가 상한 131 안쪽이다. `convert`는 `forbidWords`·`forbidLemmas`가 없으면 불변식 2를 건너뛴다.

### 4-2. 문항 목록


### 4-3. 난이도 축 — 쉼표 유무

```
난이도 1   쉼표 2개.  "~나서자," 에서 끊으면 된다 — 끊을 자리가 표시돼 있다
난이도 2   쉼표 0개.  "둘러앉아" "칠 때마다" 같은 연결어미에서 스스로 찾아야 한다
```

`[SE-01]`이 가르치는 것은 "끊어라"가 아니라 **"어디서 끊느냐"**다. 쉼표를 걷어내면 그 판단만 남는다.

**모든 문장이 18자를 넘게 짰다.** 그래서 문장 단위로만 끊으면 `긴 줄`에 걸리고, `[SE-01]:945`의 문장 안 개행이 강제된다. 뚫기 표본 `sentence-only`가 이걸 감시한다.

### 4-4. 지문 문체 — 세션 6이 두 번 다시 썼다

**첫 판이 나빴다.** 짧은 문장에 명사형을 규칙적으로 끼워 넣은 꼴이었고, 사용자가 "너무 AI같고 어색하다"고 지적했다. 재보니 이랬다.

```
54문장 전부 ~다 종결.  명사형 0개.  연결어미로 이은 문장 0개.  부사 0.  쉼표 0
```

사람이 쓴 산문에 저런 수치는 안 나온다. 그리고 `[SE-03] 종결어미 다양화`(02강의 961~963)가 정확히 이걸 지적한다.

**고치니 훈련이 나아졌다.** 연결어미로 이으면 문장이 18자를 넘고 **쉼표가 끊는 자리가 된다.** 첫 판의 난이도 2는 `"소리 없이"` 같은 말을 덧대 억지로 길이를 늘린 것이었다.

**지문에 대한 판단이 바뀐 지점도 적어둔다.** 처음엔 "7단계 지문은 학습자가 고치지 않고 그대로 읽으니 좋은 산문이어야 한다"고 했는데, 절반만 맞다. 학습자는 **읽고 나서 다시 배치한다.** 지문은 고칠 대상의 "전" 상태이고, **자연스러운 산문이면서 안 끊겨 있기만 하면 된다.**

### 4-5. 지시문 (8문항 공통, 키워드만 다름)

```
한 덩어리로 붙은 글을 끊어 읽히게 다시 쓰시오. 내용은 그대로 두고 줄만 나눕니다.
문장이 길어서 문장 단위로만 끊으면 줄이 넘칩니다. 문장 안에서도 끊으십시오.
7~13줄로 나누고, 한 줄은 18자를 넘기지 마십시오. 같은 줄을 되풀이해 채우지 마십시오.
분량은 111~131자로 유지합니다. 덜어내는 훈련이 아닙니다. '<키워드>'는 반드시 남깁니다.
```

196자다. 6단계 감각 지시문이 219자로 이미 화면에서 돌고 있어 그보다 짧다. **선언하지 않은 규칙은 학습자에게 오탐이다**(세션 3 4-6). 그래서 숫자를 다 적는다.

첫 문장이 화면에서 제목(`h1`)이 된다(`50ffd62`).

`같은 줄을 되풀이해 채우지 마십시오`는 실제 규칙(`maxDuplicateLines: 2`)보다 **약간 엄격하다. 일부러 그렇게 했다** — 지시문이 규칙보다 엄격하면 지시를 따른 학습자는 반드시 통과한다. 반대 방향이면 오탐이 난다.

## 6. 이번 세션에 배운 것

### 6-1. 검증 방식 자체가 오탐을 가릴 수 있다

**이번 세션에서 가장 값진 발견이다.**

세션 6은 모범답안을 `autoBreak` 하나로만 만들었다. 그 함수는 문장 경계를 무시하고 이어 채워서 **문장 꼬리가 앞줄에 흡수된다.** 그래서 중복이 생기지 않았고, `distinctLines`의 오탐이 픽스처에서 보이지 않았다. 세션 6은 "어긋남 0건"이라고 보고했다.

사용자가 학습자가 실제로 하는 방식(**문장마다 끊고 채우기**)으로 돌려보고 `rh-axe-pond`에서 오탐을 찾아냈다.

```
autoBreak     ... 거짓말처럼 잔잔해져 / 있었다. 도끼는 이미 바닥까지 가라앉아 ...   중복 없음
sentenceFill  ... 거짓말처럼 잔잔해져 / 있었다.        ← 홀로 떨어진다
              ... 찬 기운이 오래 남아 / 있었다.        ← 또 떨어진다. 중복
```

**뚫기 표본을 늘리는 것만으로는 부족하다. 좋은 답안을 만드는 방식도 여러 개여야 한다. 하나의 생성 방식은 하나의 시야만 준다.**

그래서 `cleanCases()`가 3종(손끊기 · `autoBreak` · `sentenceFill`)을 낸다.

### 6-2. 한 문항으로 검증하면 못 보는 것이 있다

같은 세션에서 두 번 겪었다.

```
1회  흥부 하나로만 뚫기를 돌렸다  →  "가장 짧은 문장을 여덟 줄 복사"가 통과하는 것을 못 봤다
                                 여덟에 돌리자 kongjwi 와 axe-pond 에서 샜다
                                 흥부가 막힌 것은 첫 문장이 짧아 하한 아래로 떨어진 우연이다
2회  distinctLines 를 넣었다      →  axe-pond 의 자연스러운 답안이 걸리는 것을 못 봤다
```

**"흥부는 통과한다"는 "설계가 막는다"가 아니다.** 우연히 다른 검사에 걸린 것일 수 있다. 어느 검사가 잡았는지 항목별로 확인해야 한다.

### 6-3. 화면 단계를 먼저 밟는 판단이 옳았다

사용자가 "문항 여덟을 다 만들기 전에 한 문항으로 화면까지 밟자"고 했고, 그 결정이 7단계와 **무관한 버그 하나를 드러냈다**(7-1). `rows` 하나 보려고 연 화면에서 나왔다.

**검사가 아직 없는 단계에서는 문항 수가 병목이 아니다.** 세션 3의 4-8("병목은 문항 수")은 검사가 이미 서 있는 단계에 대한 말이다.

### 6-4. 재현 쿼리를 지어내지 마라

`seed/dump/*.json`은 `order by` 없이 뽑힌 파일이다. **순서는 재현 대상이 아니라 보존 대상이다.**

세션 6이 `order by s.order_no, p.id`를 추측해서 냈다가 diff가 1316줄이 됐고, 그 상태로는 "의도한 두 곳만 바뀌었나"를 확인할 수 없었다. 되돌리고 `scripts/merge-dump.py`로 다시 갔다.

**파일이 이미 있으면 그 파일이 정답이다.** 정렬 규칙을 짐작하지 말고 재라.

### 6-5. 낡은 주석은 현재 상태로 읽힌다

`seed_verify.sql`의 확인 쿼리가 `maxAdverbs`·`minVerbs`만 봐서 6단계 8문항(`forbidLemmas`)을 "형태소 불필요"로 잘못 세고 있었다. **숫자 15는 맞고 쿼리가 틀렸다.** 불변식 2는 `forbidLemmas`가 생겼을 때 같이 고쳐졌는데 이 확인 쿼리는 안 고쳐졌다.

지금은 6개 키 전부를 보고 `→ 23`이다. 이 배열은 `morph.ts`의 `gradeMorph`, `local.ts`의 `pendingMorphChecks`와 같아야 한다.

### 7-1. 판정이 끝난 문항까지 "아직 덜 봤다"고 말하고 있었다 (`0dc9737`)

## 10. 정정 사항

### 10-1. `[SE-02]` 오인용

세션 5 문서 7장의 **"'대사와 지문'은 `[SE-02]`가 근거가 된다"는 틀렸다.**

`[SE-02]`(02강의 953~959)는 대사 비율이 아니라 **독백과 대화를 섞어 쓰기**다. 8단계 `dialogue_ratio`의 summary `"대사가 설명을 떠맡지 않게 한다"`도 근거가 확인되지 않았다.

**8단계에 들어갈 때 `rhythm`과 같은 절차로 다시 봐라** — 원문을 정독하고, 근거가 없으면 summary를 고치고, 고친 근거를 적는다.

### 10-2. `rows` — 넘어가기로 한 것

`components/train/TrainClient.tsx`가 `rows={cfg.minLines != null ? 13 : 6}`이다.

7단계 모범답안이 화면에서 차지하는 줄 수는 빈 줄 포함 13~14다. **13일 때 넷(흥부·오누이·토끼·도깨비)은 맞고 넷(심청·콩쥐·나무꾼·견우)은 마지막 한 줄이 스크롤 뒤로 넘어간다.** 화면에서 확인했다.

세션 6이 15로 올리자고 했고 **사용자가 "크게 상관없다"고 판단해 그대로 뒀다.** 나중에 올리려면 숫자 하나만 바꾸면 된다.

`constraint_types`는 20종이라 적혀 있는데 JSON에 실제로 쓰인 것은 **38종**이다. 판정 가능성으로 분류해 셌다.

| | ch01 문장 | ch02 시점 | ch03 장면 |
|---|---|---|---|
| 지금 그대로 판정됨 | 24 (19%) | 17 (24%) | 12 (9%) |
| 문자열로 신설하면 됨 | 75 (60%) | 3 (4%) | 39 (29%) |
| 형태소 서버 필요 | 27 (21%) | 9 (12%) | 0 |
| **판정 불가 섞임** | **0** | **43 (60%)** | **84 (62%)** |

**ch01은 훌륭하다. 판정 불가가 0건이다.** ch02·ch03은 60%가 설계서 자신의 원칙 3을 어긴다(`require_reader_advantage`, `min_foreshadow_count`, `max_pov_characters`, `min_scenes` 등 — 의미 판단이라 AI 심사 항목이다).

**설계서의 `1-07 개행 설계`를 우리 뚫기 표본으로 돌려봤다.** 제약이 `min_line_breaks 3` + `max_sentences_per_block 3`인데 **여섯 뚫기 중 넷이 통과한다.** `min_line_breaks`는 세션 6이 후보 A로 재보고 폐기한 그 형태다.

## 12. AI 심사 — 현황과 붙이기 전 조건

### 12-1. 현황


**AI 심사는 배선만 깔려 있고 연결이 안 돼 있다.** 2단계 `emotion_action`(`scoring_mode: hybrid`)이 "규칙은 끝났고 AI 차례인데 AI가 없다"는 안내를 띄운다(`bec064b`). 그것이 AI가 도는 것처럼 보일 수 있다.

`골든셋 7개`도 AI용이 아니다. `"용왕은 화가 났다"` 같은 **규칙 회귀 표본**이다.

### 12-2. 사용자가 Gemini 유료 키를 갖고 있다

설계서로 방향을 잡은 이상 AI 심사는 임계 경로다. **다만 붙이기 전에 셋을 먼저 푼다.**

