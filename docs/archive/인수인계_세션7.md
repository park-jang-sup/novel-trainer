## 4. 지문 — 어떻게 만들었나

### 4-1. 꼴

```
서술 1줄 + 대사 3줄. 독백 0. 지문 61~78자 (폭 17)
난이도 축은 화자 수 — 2명이면 1, 3명이면 2
```

**화자 수를 축으로 고른 이유.** 대사 줄 수(3 vs 4)를 축으로 쓰면 답안 길이가 달라져
밴드를 문항마다 갈라야 하는데, 7단계는 8문항이 밴드 하나를 공유한다. 화자 수는
밴드를 안 흔들면서 "누구의 속마음인가"를 학습자가 정하게 만든다.

**서술 1줄을 넣은 이유.** 처음엔 대사 3줄만 줬는데, 사람이 답안에 서술을 넣었다.
이유를 물으니 **"지문이 맥락을 안 줘서"** 였다. 지문이 무대를 세우면 그 이유가 사라진다.

### 4-2. `chain` 을 지우지 마라

기계는 대사의 논리를 못 잡는다. 그래서 **적게 강제한다.**

```ts
chain: [string, string, string]   // 대사 셋이 왜 그 순서로 이어지는지
```

**v1 지문에 논리 구멍이 있었다.**

```
"처마 밑에 제비가 다리를 다치고 떨어졌소."
"아이들 먹일 것도 없어요."          ← 거두자는 말이 없는데 먹이 걱정이 나온다
"그래도 매어서 보내기는 하겠소."      ← 보낼 거면 먹일 일이 없다
```

쓴 사람이 흥부전을 알아서 빈칸을 머릿속으로 메워 읽었고, **화면에 올릴 때까지 아무도 못 봤다.**
사람이 답안에서 서술로 그 구멍을 메우고 있었던 것이 단서였다.
`chain` 2번 항목에 "거두자는 말이 있어야 성립한다"고 적으려는데 그 말이 지문에 없었다.

### 4-3. 지문 규칙 검사

`lib/scoring/fixtures/passage-rules.ts` — **9·10단계 지문도 이걸 통과해야 한다.**

```
keyword 두 글자 이상 · 지문에 존재 · 흔한 말에 안 샘(LEAK_PROBE 대조)
대사 종결어미가 서로 다름 (말투 구분의 근사 — 1부 12-1:270)
종결이 전부 ~다는 아님 ([SE-03])
지문 길이 폭 · 난이도 분포 · tone 분포 · sourceKey 중복
```

**`keyword` 는 반드시 두 글자 이상이다.** 한 글자는 부분 문자열 검사에서 사실상 늘 참이다.

```
간 → 시간 · 간다 · 간신히      혹 → 혹시 · 혹은      신 → 신중 · 신하
다리 → 다리를 건넜다 (교량이 아니라 신체다. 뜻이 달라도 같은 글자다)
```

이 검사가 실제로 셋을 잡았다 — `도끼`가 `도끼눈`에 새는 것, 별주부 대사가 토끼와
종결어미가 겹치는 것, 그리고 **서술 줄 정의가 틀린 것**(아래 9-3).

## 5. 판정을 어떻게 정했나

### 5-1. `requireMonologueBetween` — 줄이 아니라 문자 인덱스

```
첫 큰따옴표 쌍의 여는 위치 < 어떤 작은따옴표 쌍 < 마지막 큰따옴표 쌍의 닫는 위치
```

**줄 번호로 재지 마라.** 표본 8건 중 한 자리에서 갈렸다.

```
"네 간이 어디에 있느냐." '없다고 하면 죽는다.' "뭍에 두고 왔습니다."
  문자 인덱스 → 통과    줄 번호 → 걸림
```

한 줄에 몰아 쓴 답안이다. 957행은 순서를 말하지 배치를 말하지 않는다.
줄 번호로 재면 개행 안 했다고 벌하게 되는데 그건 7단계 규칙이다.

### 5-2. 표기 — `''` 는 실무 관례다

```
""  일반 대화     7종 문서 1건 (02강의:958)  ·  실무 관례
''  독백·속마음   7종 문서 0건               ·  실무 관례 (사용자 증언)
[]  초월적 존재   작가 취향. "" 를 써도 상관없다 — 필수가 아니다
```

**문서 근거가 아니라 사용자 증언이라는 점을 적어 둔다.** 다음 사람이 7종을 뒤져
`작은따옴표 0건`을 보고 "근거 없이 만든 규칙"이라 판단하는 것을 막아야 한다.

`02강의:958` 의 큰따옴표는 **녹취자의 선택**이지 강사의 표기 지시가 아니다.
그 줄이 `(독백)` 이라고 따로 주석을 단 것이 증거다 — 따옴표만으로는 구별이 안 되니까.
같은 이유로 **958행의 `→` 화살표와 "다시 주인공이 말한다"도 강사의 순서 설명이지
소설 본문이 아니다.** 한 줄에 두 잣대를 대지 마라.

### 5-3. 값의 근거

```
maxChars 200
  사람이 실제로 쓴 답안이 147자였다 (지문 75 + 독백 46 + 서술 26).
  135는 짧은 독백(16~18자)을 쓸 때나 맞는 수였다.
  독백 하나는 78자까지, 독백 둘은 46자까지 200 안에 든다.

maxLineWordRepeat 6
  좋은 답안 최대반복 3 (강조 반복), 뚫기 최소반복 20. 사이가 비어 있다.
  3도 되지만 "안 된다. 안 된다. 정말로 안 된다." 같은 강조가 흔해 여유를 뒀다.

maxNarrationLines 3
  정리.md:35 "대화·독백 위주로"가 정하는 경계는 서술이 대사를 넘지 않는 것.
  지문의 대사가 3줄이니 3까지가 그 안이다. 4부터 넘어선다.
  2에서는 "하..." 같은 한숨을 따옴표로 감싸느냐로 판정이 갈렸다 —
  쓰는 사람은 둘 다 쓴다. 표기 취향이 판정을 가르면 안 된다.
```

## 6. 지시문 — 목록으로 옮겼다

지시문이 안 읽히는 문제를 네 번 겪었다.

```
1차  규칙 7문장 나열            작은따옴표 ✗  분량 ✗
2차  예시로 바꿈                표기 ○  분량 ○  위치 ✗
3차  위치 문장 되살림            전부 ○  (다만 모범 답안을 옮겨 적은 것이었다)
4차  숫자를 오른쪽 목록으로 옮김   표기 ○  위치 ○  분량 ✗  서술 ✗
```

**갈리는 선은 위치가 아니다.** 맨 마지막 항목(`제비`)이 지켜지고 세 번째(따옴표)가
안 지켜졌다. 진짜 선은 이것이다.

```
가만두면 지켜지는 것    대사 그대로 · 줄 중복 · keyword · (목록이 생긴 뒤) 표기 · 위치
새로 세어야 하는 것     분량 · 서술 줄
```

**분량은 지시문에 적어도, 목록에 띄워도, 화면에 실시간 카운터가 있어도 안 지켜진다.**
쓰는 동안 세지 않기 때문이다. 그래서 문구가 아니라 **값을 넓히는 쪽**으로 풀었다.

### 지금 지시문 (225자)

```
대사 사이에 속마음을 한 줄 끼워 넣으시오. 이렇게 됩니다.

  [예시 다섯 줄]

나머지 기준은 오른쪽에 있습니다.
```

**무엇을 빼고 남겼는지 기준이 다르다.**

```
뺀다   여덟 자 · 대사와 대사 사이 · 서술 한 줄 · 분량
       전부 목록에 숫자로 떠 있다

남긴다  "속마음은 작은따옴표로 감쌉니다"
       목록에는 "독백 수 1개 이상"으로만 뜬다. 그것만 보고 표기 방법을 알 수 없다

남긴다  "원래 서술과 대사는 그대로 둡니다"
       목록에 대응 항목이 없다. 검사로 안 재는 것이라 말로만 전할 수 있다
```

## 7. 지시서 쓰는 법

이번 세션의 지시서 여덟이 잘 돌았다. 공통 골격이다.

```
왜            무엇이 문제였고 어떻게 드러났는지. 실측값을 넣는다
무엇을         파일별로. 표로 key·label·detail·rule
하지 말 것      버린 안과 버린 이유. 이게 없으면 다시 시도한다
검증 신호      목표 수를 줄 수 있으면 주고, 못 주면 "실제 수를 보고하라"
              맞추려고 고치지 말고 멈추라고 적는다
따로 보고할 것   오탐 · 미검출 · 밴드 의존 · 감도 확인
```

**목표 수를 못 줄 때가 있다.** 표본이 늘고 주는 곳이 섞이면 셈이 안 선다.

**커밋 본문에 측정값을 남겨라.** `scrollbar-gutter: stable` 한 줄만 있으면 목적을
모르니 리팩터링 때 조용히 사라진다. `805 vs 820, 차이 -15px` 이 함께 있으면 안 사라진다.

## 9. 이번 세션에서 틀린 다섯 — 전부 같은 병이다

**표본이 실제보다 좁으면 `오탐 0` 은 검증이 아니라 미검증이다.**
다섯 번 다 수가 잡았지 눈이 잡은 게 아니다.

### 9-1. 좋은 답안 생성기가 서술을 안 만들었다

`maxNarrationLines: 0` 의 `오탐 0/24` 는 생성기가 서술을 한 줄도 안 만들어서
나온 수였다. 반응 서술판을 넣자 `mnl=1` 이 24건을 막았다.

### 9-2. 지시서에 조건을 적고 실측하지 않았다

"내용 통째 교체 상수는 밴드 안에 있어야 한다"고 적어 놓고 그 상수를 재지 않았다.
68자였고 하한 75에 7자 모자랐다. **`test:scoring` 이 잡았다.**

### 9-3. 서술 줄 정의가 틀렸다

```python
def is_speech(l): return l.startswith('"')      # 큰따옴표만 본다
def narration_lines(t): ... not is_speech(l)    # 독백 줄이 서술로 세어진다
```

좋은 답안의 서술 줄 수가 `{2, 3}` 으로 나온 것이 단서였다. **1이어야 했다.**
눈으로는 안 보이는 종류다.

### 9-4. 밴드가 뚫기를 대신 막고 있었다

상한 135 → 200 으로 넓히자 `같은 어절 30회` 뚫기가 여덟 문항 전부 통과했다.
`밴드 의존 0/112` 는 **그 뚫기가 표본에 없어서** 나온 수였다.
`250` 으로 넓혀도 같았다 — 상한이 할 일이 아니었다.

### 9-5. 표본이 만든 수를 근거로 착각했다

```
maxNarrationLines 2   "지문 1줄 + 반응 1줄" 이라는 내가 만든 조합의 관찰이었다
maxChars 135          내가 만든 짧은 독백(16~18자) 표본에서 나온 수였다
```

**둘 다 근거가 아니라 표본이었다.** 진짜 근거는 `정리.md:35` 였고,
그것이 정하는 경계는 다른 값이었다.

### 그래서 얻은 절차

```
1  넓히기 전에 "넓히면 무엇이 새는지" 뚫기를 새로 만들어 본다
   밴드 의존 감시는 이미 있는 표본만 다시 돌린다. 새로 열리는 구멍은 못 본다

2  감시가 실제로 짖는지 값을 일부러 깨서 확인한다
   빈 rule 을 하나 넣어 감시가 124건을 잡는 것을 봤다. 되돌린 것도 diff 로 확인했다

3  값을 정할 때 위아래로 흔들어 본다
   maxLineWordRepeat 6 → 3 으로 낮춰도 안 걸리고, 2 로 낮추면 걸린다
   → 표본이 경계에 붙어 있다는 뜻이다. 한쪽만 보면 모른다

4  좋은 답안 생성기가 규칙이 막는 것을 만들게 하라
   안 만들면 그 규칙의 오탐은 영영 0 으로 나온다

5  사람이 쓴 답안 하나가 픽스처 수십 건보다 많은 것을 잡아낸다
   이번에 지문 논리 구멍 · 밴드 · 서술 줄 · 입력창 버그가 전부 거기서 나왔다
```

**그리고 쓴 사람은 자기 글의 결함을 못 본다.** 지문·표본·지시서 전부 그렇다.
눈으로 읽어 확인했다는 말은 확인이 아니다. 수를 내서 대조하라.

**다만 그대로 쓸 수 없는 이유가 셋이다.**

```
난이도 축이 "설명→대사"와 "독백 끼워넣기"를 섞는다
constraints 에 min_dialogue_ratio 가 있다 — 정리.md:156 이 지목한 지표다
```

`말투 구분`은 설계서 `5-01 배경→말투`(출처 `1부 12-1`)라는 별도 드릴로 예약돼 있다.
