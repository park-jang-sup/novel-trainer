## 2. 9단계가 어떻게 섰나 — 검사를 조이지 말고 재료를 바꾼다

**이번 세션에서 가장 값진 것이다. 두 번 연속 같은 모양이었다.**

설계서 `ch02_pov.json` 의 `require_sense_verb` 를 `requireAny` 로 그대로 옮기면
**양쪽으로 틀린다**(실측).

```
뚫기   "하늘에 별이 떠 있는 것이 보였고, 남자 둘 여자 하나가…"   완전 조망인데 통과
오탐   "태윤은 하늘로 눈을 들었다. 별이 낮게 걸려 있었다…"       밀착인데 실패
```

`"보였다"` 라는 낱말의 유무는 밀착의 지표가 아니다. **재는 축이 어긋나 있어서
조여도 넓혀도 한쪽이 틀린다.** 검사를 더해 막을 수 있는 종류가 아니었다.

재료 쪽을 두 군데 고치니 검사를 하나도 새로 만들지 않고 6 → 1로 떨어졌다.

```
(가) 지문에 시점 인물을 이름으로 세운다 → requireAny 를 그 이름으로
(나) 지문의 조망 표지 구절을 문항마다 골라 forbidWords 에 넣는다

감각동사 requireAny        미검출 5/10   오탐 2/8
이름 requireAny            미검출 4/10   오탐 0/8
이름 + 조망표지            미검출 1/10   오탐 0/8   ← 지금 안
```

**8단계 `keyword` 와 같은 모양이다.**

```
8단계   keyword           기계가 못 잡는 '내용'을 낱말 하나로 대신 잡는다
9단계   시점 인물 이름 + 세는 표현
```

10단계에서 먼저 의심해 볼 만하다. 설계서 제약을 그대로 옮겨 미검출이 나오면
**규칙을 조이기 전에 지문 쪽에 손댈 곳이 있는지 본다.**

`chain` 자리도 이어진다. 8단계는 `chain`, 9단계는 **지문 요건 한 줄**이 그 일을 한다.

```
★ 지문마다 인물이나 사물을 세는 조망 구절이 하나 있어야 한다
  이것이 없는 지문은 쓸 수 없다. 버려라.
```

종결 표현('…하고 있었다')으로만 잡으면 미검출 3, 세는 표현으로 잡으면 1이다.
**일하는 것은 수를 세는 말이지 문장 끝이 아니다.**

## 3. 값 — 전부 실측이다

```
requireAny = 시점 인물 이름        2장
forbidWords = DEICTIC + relic 둘   relic[0] 은 반드시 세는 표현
MAX_ECHO = 9                     빈 구간이 8~10 하나뿐. ★ 폭 2
minChars = 20                    빈 구간 2~29. 30이면 오탐 3, 40이면 오탐 52/64
maxChars = 130                   설계서 F3 상한
```

### `MAX_ECHO` 는 폭이 2다 — 다음 사람이 모르면 함부로 조인다

```
좋은 답안 최장   8자  "하늘에별이떠있고"
베낀 표본 최소  10자  "이야기를나누고있었다"
상한 5 → 오탐 3건. 5는 틀린 값이었다
```

8단계 `maxLineWordRepeat` 은 3~15 사이에서 6을 골랐다(폭 12). 여기는 폭 2다.
**선언 옆에 주석으로 박아 뒀다.** 실제 좋은 답안 64건의 겹침 최대는 4자라 여유가
있어 보이지만, 폭 2는 *일부러 재사용을 넣은* 표본에서 나온 값이다. 그 4를 믿지 마라.

### `gaze` / `stage` 를 나눈 것이 핵심이었다

지문 전체를 겹침 대조 대상으로 삼으면 **빈 구간이 사라진다.**

```
좋은 답안 K  '태윤은 담장 아래 서서…'    8자
베낀 표본 W  '…하늘에 별이 떠 있고…'    8자
→ 8~8. 값을 못 고른다
```

무대 설정 줄은 답안이 살려도 되는 부분이다. 대조 대상을 `gaze` 로 좁혀야 8~10이 생긴다.
`stage` 를 다시 넣지 마라.

## 4. 알려진 한계 — `내용 통째 교체`

```
'내용 통째 교체'  →  pass 가 정상이다
```

이름을 박고 내용을 통째로 바꾸면 통과한다. `local.ts:481~486` 이 서술형 채점 전체의
한계로 적어 뒀고 8단계도 같은 구멍을 안고 나갔다. `known: true` 로 표본에 박아

**이것이 fail 로 바뀌면 누군가 규칙을 조인 것이다.** 그때는 좋은 답안 오탐이 함께

7단계 `knownGapCase` 와 방향이 반대다. 저기는 실패가 좋은 소식이지만
여기서는 **통과가 정상이고 실패가 경보**다.

## 5. `seed_data.sql` 을 편집기에 붙여 넣으면 새 행이 오염된다

**이번 세션 최대의 함정이다. `seed_check.sql` 이 잡아 줬다.**

```
seed_data.sql    개행이 SQL 문자열 안에 '실제 줄바꿈'으로 들어 있다
                 sqlStr 이 이스케이프를 안 한다. 파일 자체는 LF 뿐 (CR 0개)
Supabase 편집기   붙여 넣으면 textarea 규격대로 LF → CRLF
                 문자열 안의 줄바꿈까지 함께 바뀐다
결과             instruction 217 → 227 (개행 10개)
                 passage      63 → 64 (개행 1개)
                 차이가 정확히 개행 수와 같다
```

기존 69건이 멀쩡했던 이유는 `insert ... where not exists` 라서다. `mo-*` 8건도 개행을
갖고 있지만 **이미 있어서 건너뛰었고**, 새로 들어간 `pv-*` 8건만 오염됐다.

**우연히 지켜진 것이다. 다음 단계에서 똑같이 난다.**

### 났을 때 메우는 법

```sql
update problems
   set instruction = replace(instruction, chr(13), ''),
       passage     = replace(passage,     chr(13), '')
 where instruction like '%' || chr(13) || '%'
    or passage     like '%' || chr(13) || '%';
```

## 7. 이번 세션에서 틀린 것

**전부 수가 잡았지 눈이 잡은 게 아니다.**

### 7-1. 밴드가 검사를 대신 막고 있었다 — 세션 7 §9-4 재발

첫 측정에서 `minChars 40` 을 잠정으로 넣고 재서 **미검출 0/7** 이 나왔다. 거짓이었다.
밴드를 떼자 미검출 6/9 가 드러났다.

```
minChars   밴드로만 잡히는 뚫기   좋은 답안 오탐
    0              0                2
   40              5                4
```

**감도 확인 없이 밴드를 넣은 채로 재지 마라.** 같은 병이 세 세션 연속이다.

### 7-2. `tsc --noEmit` 을 마지막에 안 돌렸다

`[DEICTIC 누출 감시]` 블록에서 앞선 블록 안에 선언된 `DumpProblem` 을 참조했다.
인터페이스는 블록 스코프라 안 보인다. **`tsx` 는 런타임에 타입을 안 보므로
1172 통과 아래에 컴파일 오류가 숨어 있었다.** 클로드 코드가 잡았다.

```
test:scoring 이 통과해도 tsc 는 따로 돌려라. 서로 다른 것을 본다
```

### 7-3. `app/` 의 tsc 오류 셋을 '기존 오류'라고 적었다

지시서에 "c2acf66 에서도 나는 기존 오류니 고치지 마라"고 썼다. **틀렸다.**
`LayoutProps`·`PageProps` 는 `npx next typegen` 이 `.next/types/` 에 만드는 전역 타입이고,
`tsconfig.json` 의 `include` 가 그 경로를 잡는다. 갓 클론한 환경에서만 뜬다.

**세션 8 §0-2가 이미 `npx next typegen` 을 적어 뒀다. 내가 안 읽었다.**
인수인계에 있는 것을 다시 틀리는 것이 가장 나쁘다.

### 7-4. 내가 만든 재료에서 부분 문자열 병이 났다

8번 문항 뚫기에 `여기저기` 를 썼다가 `DEICTIC` 의 `저기` 에 걸렸다.
세션 7 §4-3 의 '한 글자 금지'와 같은 병이다. 검사가 잡았다.

찾는 김에 넷을 실측해 `DEICTIC_REVIEWED_COLLISIONS` 로 남겼다 —
`여기저기` · `이쪽저쪽` · `저기압` · `저기요`. 실제 발생 0/193.
`convert-seeds.ts` 의 `reviewedCollisions` 와 같은 자리다.

### 7-5. 지시서에 적은 수 둘이 실제와 달랐다

```
verify 패치 +348  →  실제 +353   (7-2 수정 5줄)
app/ tsc 오류 셋   →  7-3
```

목표 수 1172는 맞았다. **목표 수를 미리 박아 둔 것이 이번에도 일했다** —
클로드 코드가 차이를 스스로 보고했다.
